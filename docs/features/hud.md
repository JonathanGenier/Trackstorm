# In-Match Combat HUD

[Shared weapon aiming](weapon-aiming.md) adds a compact square fixed at the camera viewport center. Direct center-ray intersection with another living, visible car replaces it with four disconnected red/white corner brackets, including at close range. Looking away or hitting cover returns to the centered square. Accepted item aim supplies readiness color, while native camera queries supply the viewed target; neither brackets nor the square claim perfect firing alignment. The overlay clears on selection/lifecycle/suppression/resync boundaries and adds no HUD gameplay authority.

## Behavior and Layout

Network starts add a temporary center-screen **5 → 4 → 3 → 2 → 1 → GO** overlay above the existing HUD. Outlined cream numerals, an amber ring/start lights and a mint GO provide contrast over the arena; each value settles with a brief scale animation. The accepted authoritative phase and world tick select the value. Animation time never authorizes gameplay. GO fades and clears within 0.75 seconds, leaving the permanent HUD in place. See [Game Loop](game-loop.md) for the full-roster synchronization gate and timing ownership.

During a production practice or network arena, the HUD shows a bottom-left standing badge and current/max HP, a bottom-right speedometer and two held-item slots, and a top-center timer. Standing uses the same authoritative [match standings](standings.md) rank as the leaderboard during network matches; practice displays `--`. Network Circus matches add a compact upper-left banked total and current K/D multiplier below the arena status strip. The existing top-center timer displays Circus authoritative remaining time as MM:SS: `10:00` by default, through `00:00` at expiry. It rounds remaining ticks up to seconds and reads the accepted Game Loop time boundary plus the latest accepted host world tick, never prediction or a HUD clock. Initialization/countdown show the full configured Active duration. Join/reconnect immediately project the installed checkpoint; migration uses the restored time and recovery debit. Host duration edits update this same display. Untimed FirstToTarget and practice retain `--:--`. The HUD disappears when the local vehicle is unavailable or the arena closes.

Below the persistent Circus total, temporary feedback uses one row per authoritative category: Kill, Collision, Drift, Airtime, Long Jump and Top Speed. Current stunt state renders yellow `PENDING` values that update in place and may coexist. Committed category-attributed deltas render as `BANKED` and linger for 1.8 seconds with a 0.5-second fade; repeated discrete awards replace and refresh their category row. If an authoritative scored death clears pending stunt state, each affected category briefly renders red `LOST` without changing the banked total. Initial/late-join snapshots establish current totals and pending state without replaying historical award deltas. The Client drains every accepted match revision so short-lived awards cannot disappear when several reliable publications arrive in one rendered frame. Local practice has no Circus presentation.

Health uses the actual `VehicleSnapshot.Damage.CurrentHP / MaxHP`. Production vehicles, including the Release 0.1.0 hosted preset, spawn with 1000 HP; future capacities require no HUD formula changes. The red segmented health bar decreases and increases immediately with the committed health fraction. Speed uses `VehicleSnapshot.Speed`, the existing observed horizontal speed in metres per second, and the current local unit preference. Only the number converts to km/h or mph. The red arc fills at 200 km/h (55.555… m/s) in either setting, and clamps at full above that speed. This is a visual scale, not a new physical speed cap.

Empty, Wrench, Missile, Oil, Nitro, Proxy Mine, Salvo and Machine Gun have distinct local slot presentations driven by the shared item registry. Salvo displays its confirmed remaining ammunition in each physical slot (for example, SALVO 4); Machine Gun displays the confirmed remaining magazine percentage (for example, MACHINE GUN 38%). Exhaustion shows Empty. Item identity comes from the existing confirmed two-slot record, matched to the local vehicle and life; dead/respawning vehicles and unavailable or mismatched slots show Empty. There is no predicted pickup or item consumption. Existing remappable item inputs use the normal item path. Arena diagnostics live in DevTools [Stats](statistics.md), while grant/reset controls remain in [Developer Options](developer-options.md) Configs; Arena Tools and its duplicate Use held item button are retired. Session leave and settings actions use the [ESC Game Menu](game-menu.md); no permanent Settings, Return or Leave button remains in the arena. The obsolete settings diagnostic speed line is removed entirely; the combat speedometer remains unchanged, and independent FPS/ping preferences still apply. Compact FPS/Ping diagnostics share one row at the upper-right, with 8 pixels above and 16 pixels to the right. The 208-pixel region fits above the centered standings board, including its decorative edge, at the smallest supported 640×360 size and remains clear of the bottom HUD and top-center timer.

The bottom-right speedometer and two physical slots share one scaled assembly anchored flush to the bottom and right viewport edges. Its flat baseline/right boundary and shallow armored shoulders conserve gameplay space. Rusted beveled rails, restrained upper/left spikes, bolts and a recessed skull divider retain the Carnage identity. Slot numbers remain stable; a yellow perimeter follows the selected physical slot, including when empty, without ACTIVE/SELECTED wording. Each slot binds its own identity, optically centered icon and optional resource independently of selection. Replacement, removal, life changes and missing inventory clear obsolete content immediately. The separate bottom-left HP artwork and binding retain their existing placement and common scale.

## Remote vehicle tags

Network arenas show each connected remote player's canonical `SessionPlayer.Name` above their vehicle, with a compact red HP bar directly below. The bar reads that vehicle's latest accepted `VehicleSnapshot.Damage.CurrentHP / MaxHP`, independently of delayed pose interpolation. There is no numeric HP text or additional tag data. Local vehicles and practice targets have no world tag.

`NetworkVehicleArena` creates one `RemoteVehicleTag` child when it creates a remote `NetworkVehicleBody`. The tag follows the body's rendered position with a world-up offset; its complete transform uses the local chase camera's axes, so vehicle heading, pitch and roll cannot tilt the name or bar. Label and bar retain depth testing and fixed world dimensions, with no through-wall rendering or distance rules. Godot's existing font and native quad geometry require no new assets.

Names come from the current [session roster](sessions.md), joined by the same stable player/vehicle ID used by replication. Render refreshes update existing label/mesh properties without retaining gameplay health. Inactive vehicles hide their tags; the existing [respawn boundary](death-respawn.md) restores presentation and full authoritative HP. Disconnected reservations hide their tags, and [resume checkpoints](reconnection.md) restore the same body-owned tag from current identity and health. Final vehicle removal or arena teardown frees its child tag. Fresh active admission reconstructs these same tags from the current checkpoint and committed session roster; it creates no parallel presentation path. See [session bootstrap](sessions.md#fresh-admission-during-an-arena).

The native lobby harness checks all eight peers, subsequent lobby joins, repeated matches, local exclusion and departure cleanup. Native render fixtures cover full/damaged/healed/zero HP, life changes, Unicode labels and vehicle/camera rotation. The two-peer reconnect harness checks replicated health, actual Wrench healing, collision death and timed respawn, plus three reconnects retaining the original tag and changed health capacity. These checks run through `check-lobby.ps1` and `check-reconnect.ps1`; `-Visual` captures the rendered arenas. They do not establish separate-PC EOS behavior.

## Presentation Ownership and Assets

The [player activity feed](activity-feed.md) occupies the top-right below FPS/ping diagnostics. Its five independently expiring lines use transparent, outlined text and consume the same authoritative journal as the Event Log. It remains available while the arena exists, including death/respawn, and disappears when there are no recent approved events.

`Client.Hud.CombatHudView` is a detached pure Client vehicle projection, while `CircusScoreFeedback` projects accepted authoritative match snapshots and owns only presentation linger/fade time. Both are unit-tested without Godot. `CombatHud` owns the native component Controls, labels and materials. The temporary Godot `Variant` used to hand the shared steel texture to each shader is disposed after the material copies it, so its native reference cannot outlive UI teardown through managed finalization. This does not dispose the shared texture used by the HUD, menu and standings. The bootstrap supplies functions reading the current local practice snapshot or network driver's local snapshot, accepted match revisions, confirmed inventory/selection record and preference service. Render refreshes never call gameplay mutation APIs or persistence. Session replacement is naturally reflected by these providers; the HUD holds no vehicle, score or inventory authority.

The original project-supplied Health and Timer PNGs remain in use. The corner assembly uses `CornerAssembly.png`, a blank transparent derivative of the approved shaped-armor concept. `assets/hud/sources.json` and [HUD asset notes](../../assets/hud/README.md) record hashes, the exact generation prompt and geometry. `CornerAssembly.gdshader` samples a tight visible region to remove exterior padding and draws sixteen red/orange speed segments in the recessed arc, using the existing 200 km/h visual scale. All numbers, units, item silhouettes, selection and resource rails remain live. The assembly uses installed Impact, then Roboto Condensed/Arial Narrow, then Godot fallback; no font file is redistributed. Other HUD typography retains its existing fonts.

`ItemHudSlotView` is the single pure Client adapter from each confirmed physical slot to identity, icon key and optional `ItemHudResource` (readout plus optional normalized fraction). Both instances share layout, selection, clearing and native lifetime under `CombatHud`; nodes are reused across grants and switches. New resource-bearing items extend the adapter and use the same ownership path. `ItemHudSlot` reads only that projection. Nitro appears as BOOST with an ivory jet silhouette, large upward-rounded percentage and five cyan segments. Each segment represents 20% charge, with spatial partial fill rather than discrete uses. Machine Gun uses a neutral gold five-cell magazine rail; Salvo remains count-only because its publication has no starting capacity. Every item retains a visible heading. Exhaustion clears the icon, value and rail to EMPTY. SVG alpha bounds are measured once on load and used as atlas regions so unequal source padding cannot offset icons. No gameplay or inventory authority moves into the HUD.

The components use a 1280x720 design coordinate system with uniform scaling at 85% of the viewport-fit size bounded by both dimensions. The corner assembly is 600x144.24 design pixels, preserving its tight approximately 4.16:1 silhouette. Its bottom-right position is viewport size minus scaled assembly size, with zero exterior margin at all supported sizes down to 640x360, including taller and ultrawide viewports. HP and timer placement remain independent. The native HUD harness checks edge equality, speed/unit separation, centered icon regions, heading separation and rendered yellow selection transfer at supported sizes.

## Capacity Integration and Verification

`HostVehicleSession` accepts explicit health configuration and applies it to host and joining players. The existing network snapshot already carries MaxHP; the decoder validates its bounded value rather than requiring the generic 100 HP default. Prediction reconstructs its health capacity from that authoritative spawn boundary. Capacity remains fixed for that registered vehicle; this change does not add runtime vehicle-type switching. The wire layout and physics/input units are unchanged. Mixed old/new builds should not share a match: older decoders reject the 1000 HP production state.

Core tests exercise configured capacities through join, wire round-trip and prediction. Pure Client tests cover unit conversion, 200 km/h normalization, current/max formatting, future capacities, all item mappings, identity/life gating, timer rounding, countdown exclusion, checkpoint/recovery projection, zero-time non-authority and non-mutating state projection. `check-hud.ps1 -GodotPath <Godot .NET executable>` renders native HUD state transitions, checks labels/materials and rendered fill pixels, verifies unit changes, rendered `10:00`, `09:59`, `00:01`, `00:00` timer labels and out-of-match hiding, checks rendered resource-pixel depletion and second-slot isolation, checks both physical slot labels/icons/resources through repeated replacements, duplicates, selection, missing and wrong-life/vehicle inventory, and saves images for nine viewport sizes under `.godot/hud-checks`. The existing eight-peer item and pickup harnesses also assert that the HUD follows confirmed replicated HP/ownership through use and acquisition. These are local-machine integration checks, not a separate-PC or Internet multiplayer soak.

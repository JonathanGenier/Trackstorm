# Player Reconnection and Session Resume

## Identity and Authorization

The returning runtime must match the canonical host [game version](game-versioning.md). Both EOS membership recovery and authoritative Resume validate compatibility. A mismatch cannot restore controls, advance connection generation or trigger checkpoint publication; the disconnected reservation remains unchanged until the match ends.

The existing lobby authority owns reconnect policy and active-match reservations. EOS Product User ID authenticates an online subject; Trackstorm SessionId identifies the logical session; PlayerId identifies a player and their vehicle; the transport peer is a temporary connection; and each player has a monotonically increasing connection generation. Neither PUID, IP address nor peer handle becomes a gameplay PlayerId. Client resolves the EOS-authenticated sender into an opaque subject supplied to Core. Core stores that subject privately for the active session; it is never accepted from a gameplay packet or included in the roster.

A resume intent carries the previously acknowledged SessionId, PlayerId and connection generation. The authority requires the same authenticated subject, a valid disconnected reservation through the current match and a fresh peer. It atomically installs the new mapping, advances the generation and retains the original name and slot. Duplicate live connections, wrong subjects/sessions/generations and ended reservations fail closed. Existing EOS handshake nonces reject old native packets; the `TG` gameplay envelope independently checks logical session and recipient connection generation before any vehicle, item, match or prop decoder runs. Transport handles increase within the gateway lifetime. Core retains only bounded current reservation state, not a growing log of retired connections.

Initial Locked-lobby admission still requires the access code. In an active match, an already admitted authenticated subject can resume its reserved slot without retaining or resending that code. A player returning after any lobby departure is instead a fresh admission and must satisfy the current Public/Locked join rules. Resume authorization remains in Core; the separate [Cloudflare lease service](authority-leases.md) holds no player reservation or gameplay state. No resume secret or long-term platform credential is introduced. New players remain unable to join an active arena.

## Match Retention, Leave and Vehicle Policy

`LobbySnapshot.ReconnectPolicy` makes the lifecycle split explicit. In `Lobby`, intentional Leave and unexpected transport or membership loss remove the player, subject binding and roster slot immediately. There is no lobby reservation or saved locator; a later return receives a fresh PlayerId. In `Arena`, every departure immediately retires input ownership and publishes `Connected = false` and `Ready = false`. The existing player record is the reservation until Return ends that match. There is no player deadline, configurable grace duration or clock-driven expiry, including after migration. Authenticated resume advances connection generation and binds one fresh peer to that same player.

While disconnected, the host retains the same authoritative vehicle and sends neutral input every step. Pending driving commands and uncommitted item-use requests are discarded immediately. While the host retains its [authority lease](host-migration.md), physics, damage, held items, missiles, pickup cooldowns, death/respawn deadlines and match scoring continue normally; a disconnected vehicle remains vulnerable, can coast or respawn, and receives no invulnerability or rewind. A non-host disconnect does not pause a healthy host, including a two-player host losing its sole client. Transient recovery keeps the same epoch. Only intentional departure or confirmed service retirement can enable replacement authority; a P2P timeout alone cannot. Existing score rows and consumed-life watermarks survive final departure according to match rules. Return ends the arena and removes disconnected reservations and their remaining vehicle/item state.

**Leave session** sends a reliable departure and waits at most one second for acknowledgement before closing the gateway. It cancels automatic recovery. In the lobby this removes the player immediately. In an arena it suspends the player with the same match-long retention as unexpected loss and preserves a manual **Resume previous session** route. Host departure follows the [migration policy](host-migration.md): player retention never delays authority retirement or grants host privileges. The native reconnect harness injects a trusted test identity over Direct-IP to exercise the shared production driver.

## Complete Arena Resync

After the lobby authorizes an arena rebind, the existing vehicle driver reconnects the new peer to the suspended vehicle and sends one reliable `TR` checkpoint. It composes the current codecs into a bounded packet below 65,000 bytes: complete vehicle identity/life, tick and input acknowledgement, HP/damage memory, transform and linear/angular velocity, handling/surface state and pending physical effects; all held slots and grant tokens; active missiles; all pickup states and absolute activation deadlines; complete match phase, countdown, target, scores, winner and consumed-life watermarks; and current movable-prop poses/velocities when the native arena is attached.

Version-two checkpoints also include the complete [host gameplay configuration and revision](developer-options.md), cross-validated against vehicle capacity, steering limits, world revision and match target. All components are decoded and cross-validated before installation. The client installs tuning before reconstructing prediction through `PredictedVehicle` at the host's current acknowledgement/tick, with no old pending inputs. The next input is acknowledgement + 1, and prediction advances from the checkpoint tick. Snapshot history is replaced with that one boundary. Remote interpolation cursor, native correction offsets, damage feedback and collision-feedback baselines are reseeded while existing native vehicle nodes retain their identities. Gameplay input stays suppressed until the complete checkpoint is installed. Arena reconstruction after process restart uses the same checkpoint path.

Checkpoint item events and score deltas are empty: current state is restored without replaying historical launches, impacts, repairs, kills or wins. Death presentation seeds current life watermarks without emitting past destruction bursts. [Arena audio](audio.md) also reseeds vehicle, item and match baselines without historical one-shots. Normal later publications retain existing revision, tick, life and grant-token duplicate protection. Other connected players continue using their existing uninterrupted prediction/replication streams.

## Recovery and Restart

The client shows **Connection interrupted**, **Reconnecting**, **Resume succeeded**, **Resume rejected** or **Session unavailable**. Re-establishment starts after one second and retries at two-second intervals. Neither transport resume nor EOS membership recovery expires a player reservation locally. Explicit Leave cancels recovery. Migration attempts retain their independent bounded fencing/agreement failure policy; a failed attempt never deletes the remote player reservation and the saved locator permits a later same-match retry. Player Ping stays unavailable until transport, admission and the arena checkpoint are current. Fresh handles/nonces own fresh samples; EOS latency-sample expiry remains independent.

Recovery is entered only from an explicit local EOS membership departure/closure
or an actual transport loss. Lobby metadata refreshes and incomplete cached member
lists cannot remove a healthy member, stop P2P or start an unsolicited resume
attempt. Member join/departure notifications remain authoritative for the roster.

`user://session-resume.json` is written only during an arena. It contains the lobby locator, expected session/host/epoch, authenticated user identity and acknowledged PlayerId/generation, with no access code, platform token, lease key or authorization secret. Every player uses the same hint with no local expiry or former-host exception. Hints are replaced atomically every five seconds while connected and after assignment changes, and survive application exit. Lobby Return, invalid data, account mismatch and authoritative rejection clear them. Active-match Leave preserves a manual resume action without automatically undoing Leave. An offline file cannot know when the match ended: it may remain until the next attempt, when Core rejects the removed player; the file itself grants no reservation or authority. Return removes all disconnected records and subject/peer history, resets connected players, and the normal arena teardown discards vehicle/item/match state before the next arena is constructed.

Resume searches by the saved EOS lobby ID and uses ordinary JoinLobby. The lobby stays publicly joinable at the provider layer while its `open` attribute hides active matches from normal discovery. Cached membership must be confirmed by a service round trip; an obsolete cache falls back to rejoin. The native-invite-only JoinLobbyById API is not a resume mechanism. This route grants membership only; the existing Core rebind checks grant gameplay access. Restart requires the same EOS identity and a current authority retaining the reservation. A crash before the newest generation was saved can leave a stale hint that is deliberately rejected. No cross-session persistence or new-player join-in-progress is provided. Host rehosting is described in [host migration](host-migration.md).

New locators also retain an optional opaque read-only lease `RoutingId`. The host learns it from an accepted service response and distributes it in authenticated migration checkpoints; ordinary clients learn it only after the current-host, session/epoch/match, roster and sequence checks accept that checkpoint. The coordinator saves a newly learned address immediately on its next tick, without waiting for the five-second refresh or a generation change. It contains no private lease key or token, and healthy clients make no service requests to obtain it.

Once membership is recovered, restart uses an authenticated [lease routing read](authority-leases.md) before attaching gameplay. This resolves the fenced host even when an ordinary client disconnected before a later host failure and EOS ownership/metadata still point at the old host. Former hosts use the same path. Self routes, regressed epochs, same-epoch host conflicts, expired grants and delayed/invalid responses keep recovery waiting and retrying; they cannot create authority or discard the retained player. Core Resume and complete arena resync remain mandatory, including for Locked sessions without password re-entry. Legacy locators without this address retain the existing metadata route and self-route guard; they cannot discover a migrated host from permanently stale EOS metadata. Update the Worker and every game peer before creating the fresh match used to verify this recovery path.

## Verification and Limits

Deterministic Core tests cover immediate lobby removal/fresh admission, match-long arena retention and Return cleanup, identity and generation validation, atomic rebind, Ready reset, old-peer retirement, capacity, repeated arena cycles, state/checkpoint serialization, prediction baseline, and death/respawn and score continuity. Provider-independent Client tests exercise production EOS framing over authenticated fake datagrams, lobby migration without reservations, repeated arena recovery, Locked retained identity authorization, stale stream rejection, restart routing and bounded file validation. They do not prove real EOS remote connectivity.

`check-reconnect.ps1 -GodotPath <exe>` exercises real local UDP sockets and two isolated native Godot worlds: immediate lobby removal/fresh admission, three arena resyncs, retained vehicle nodes, cleared input/interpolation history, HP/item/spawn/match continuity, and retention beyond the old thirty-second/two-minute boundaries followed by Return cleanup. `-Visual` captures the resumed arena under `.godot/reconnect-checks`. Existing eight-peer lobby, item, pickup, death/respawn, match and vehicle checks cover surrounding regressions. The EOS smoke check covers real authentication and lobby/P2P lifecycle with a solo host. Separate-PC EOS interruption, changed public IP, full restart during an active match and long-session Internet soak still require real-device verification using the EOS development procedure.

# Main Menu

The frontend presents Play, disabled Garage / Coming Soon, Settings and Quit. `DevelopmentSession` supplies the existing browser, Settings and cleanup-aware Quit actions to `HangingMainMenu`. Browser, lobby, Settings and gameplay presentation retain their existing owners. The separate Settings shortcut remains available on other frontend screens but is hidden on the Main Menu.

This is the only Main Menu presentation. The [Play Menu](play-menu.md) owns discovery and reconnect presentation; the legacy `LobbyBrowser` panel is retained only for the explicit Direct-IP fallback. Both are created hidden. Passive saved-session metadata lookup cannot take over the Main Menu. Returning with Direct-IP Back clears its selection; Game Menu and Podium returns share the existing cleanup gate. Local-practice return uses the same fully wired session composition as startup. Navigation synchronously disables Main Menu targets; Play hoists its visible rig clear before destination controls appear.

A non-interactive bottom-left label displays the canonical `GameVersion.Current`, with viewport-relative bottom anchoring and fixed safe margins. It belongs to the Main Menu but sits outside the hanging assembly's scale and entrance transform. The obsolete top-right diagnostic speed line is removed; independent FPS/Ping remain, and the gameplay speedometer retains its existing snapshot binding.

`HangingMainMenu.SetEntries` accepts independent IDs, labels, icon indices, availability, optional status and actions. Rebuilding changes plate count, vertical spacing, total height, viewport fit and connecting chain lengths. `HangingMenuPlate` uses a shared blank texture, independent icon atlas region, label and blank status backing. The selected shader changes color without changing the texture or alpha silhouette. [Artwork provenance](../../assets/frontend/main-menu/README.md) describes assets and typography fallback.

At the existing successful [startup](startup.md) reveal callback, the complete assembly begins above the viewport, accelerates down for 0.52 seconds, catches at its resting height, and settles with a single sub-seven-design-pixel lift over 0.6 seconds. Activation remains blocked until 1.12 seconds. No MenuShell media APIs participate in this animation. Hidden composition and every existing startup failure/retry gate remain in force. Returning from Settings retains the settled assembly. [Play Menu](play-menu.md) entry hoists this rig clear in 0.34 seconds; Back reuses its drop/catch/settle without touching media.

Upper chains draw from fixed viewport-top points to the moving header; fixed-size link sections are revealed or clipped rather than stretched. Connecting chains move with the common artwork transform during the entrance. After settling, the rigid assembly remains stationary. Only the flags continue moving: broad traveling fabric folds and a smaller faster ripple grow toward their loose ends, with the upper 24% fixed at the attachment. The stronger flutter does not transform metal, labels or native hit targets.

The complete assembly and its stationary targets share a uniform scale of 75% of the viewport-fitting size. It hangs from the viewport top with a 4%-of-viewport-width left margin, leaving the right-hand background title unobstructed. Internal spacing and animation use the same design coordinates, so the smaller left-hand placement preserves chain connections and interaction alignment.

One selection follows enabled pointer movement or logical keyboard/controller focus. Directional navigation wraps through enabled entries, skips Garage, and repeats after 0.4 seconds at 0.12-second intervals. Logical input uses the existing remappable player binding owner. Native default navigation is consumed to avoid duplicate activation. Inputs held during entrance or a covering overlay are sampled without dispatch so they must be released before activation resumes. Settings/DevTools suspend the Main Menu's targets and navigation, with selection restored afterward.

`check-startup.ps1` exercises the production Loader reveal, phase-aware retries, blocked/held activation, mixed synthetic mouse/keyboard/gamepad input, disabled Garage, repeated navigation, Settings/browser return, stable hit rectangles and exact media-player continuity. It checks that every artwork/attachment control's global transform remains fixed across six idle samples. `-Visual` captures entrance, selection and successive flag-flutter states and checks 640×360, 1280×720 and 1600×900 viewport bounds. `check-menu.ps1 -Visual` covers existing Settings/gameplay/input/cleanup integration. Audible continuity and physical-controller ergonomics require direct listening and hardware testing beyond these assertions.

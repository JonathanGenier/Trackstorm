# Player activity and kill feed

The gameplay HUD automatically shows approved presence and death outcomes at the top-right, below the FPS/ping diagnostics. There is no background panel, input capture or toggle. Five single-line rows are retained in chronological order; a sixth immediately evicts the oldest. Each row expires independently after five presentation seconds. Green indicates joins/reconnections, amber departures/disconnections, and soft red kills/deaths. Outlined plain text provides contrast without an opaque panel. Row geometry scales across supported viewports; unusually long text uses ellipsis rather than wrapping into another entry.

`Client.Hud.ActivityFeedView` subscribes directly to `Core.Events.EventStream.Appended`, after the existing journal accepts and deduplicates the event. It does not read snapshots to infer connections, damage or kills. The live callback avoids losing approved outcomes behind a burst of debug history before the next render. Only five presentation rows are stored; neither an event bus nor another event history is maintained.

The allowlist admits authoritative Session Joined/Left, Network Disconnected/Reconnected and match-reservation cleanup (worded as leaving), Lifecycle Kill, and otherwise unattributed Dead. Local diagnostics and all other categories/kinds are excluded, including unknown future events. Arbitrary cause/context/debug strings never become player-facing text. Missile is the only optional weapon suffix currently shown. Names are the sanitized session names captured by the shared event at publication, so departure and later roster changes cannot relabel a row.

The simulation marks a death's existing structured Context as `Scored kill` when the same committed match result emits its authoritative Kill event. The feed omits that redundant Dead row and renders the Kill instead. This works even when reliable replication splits the two events across batches. Scoring remains entirely owned by match authority. Self/environmental deaths and deaths outside active scoring use `Name died`; the feed never promotes a raw damage instigator to an awarded killer. No scoring or death-detection rule is changed.

Binding a journal never replays its retained history. The journal's sequence watermark and existing host/session/connection-generation fencing prevent duplicate delivery and resume replay. The HUD subscription survives in-process reconnect through the retained session journal; replacement journals detach the old subscription and clear visible rows. Leaving gameplay clears the feed, lobby events remain hidden, and HUD teardown unsubscribes. New categories should extend this allowlist over the shared stream.

`ActivityFeedTests` exercises actual presence and lethal simulation outcomes, split event packets, names, filtering, bursts beyond journal retention, independent expiry, rebinding and replay rejection. Production driver tests cover reliable replication deduplication and connection-generation rejection. `check-event-log.ps1 -GodotPath <Godot .NET console> -Visual` also checks the production feed, a real UDP departure, native five-row layout/expiry and screenshots at 640×360, 1280×720 and 2560×1080 under `.godot/activity-feed-checks`. Presentation fixtures used for visual checks are explicit structured events; they do not establish actual combat input or separate-PC EOS behavior.

# TS-30 / TS-31 implementation verification

## Scope and implementation

Implemented on the existing `ts-30-pg` Story branch. TS-31 is the sole child specification; no child branch or PR was created. The current Jira descriptions, comments and all five attachments were inspected before implementation and the descriptions were reviewed again during final verification. The approved standing clarification supersedes the original request for ordinal standings: the badge displays `--`, with no scoring authority.

The HUD uses four independently positioned component textures, native dynamic labels, red shader-driven gauges and original Wrench/Missile silhouettes. It reads existing snapshots, confirmed inventory and player settings. Production practice and network vehicles configure 1000 HP; existing health configuration, replication and prediction support that capacity and future values. No input binding or gameplay clock was added.

## Visual comparison and limitations

The supplied worn metal, spikes, red accents and dark surfaces are retained. The individual component art is the runtime basis; the full scene reference is not shipped as an overlay. Baked example values, gun caption and Q prompt are masked using the source steel texture. Live text uses Godot's cleaner default font rather than the distressed reference lettering. The standalone speed component is slightly taller than its treatment in the scene reference. Wrench/Missile silhouettes and intentional standing/timer placeholders replace reference examples. The existing prototype world and development controls remain; recreating the reference arena background was not part of this Story.

VERIFIED: rendered state changes, layout at all nine sizes, local eight-peer native transport, settings persistence and deterministic regressions. INFERRED from diff inspection: dependency ownership and absence of new scoring/input authority. UNVERIFIED: separate-PC Internet play, long-session soak and clean-machine exported builds. The unchanged wire layout carries variable MaxHP, but old builds reject 1000 HP snapshots; multiplayer validation used matching builds. No mixed-version compatibility is claimed.

# TS-46 / TS-51 verification

Date: 2026-09-15. Story branch: `ts-46-jg`. Integrated `main` through `bbe0783` (including TS-28 standings). This is historical implementation evidence, not a replacement for Jira or current verification.

## Implementation

Core owns immutable lobby continuation, explicit current host/epoch, deterministic survivor agreement, versioned checkpoints and authoritative restoration. Client owns detection/timeouts, checkpoint distribution, authenticated transport rebinding and native presentation reset. EOS ownership is coordination only. The dependency remains `Client -> Core`, with no Shared layer, new service or third-party dependency.

The main changes are in `Core/Sessions`, `Core/Networking/Replication/HostVehicleSession`, item/spawn continuation, Client lobby/vehicle drivers, `SessionMigration`, EOS transport/provider/coordinator/binding, and native arena reset hooks. The integrated standings diagnostics now carry the epoch and identify the elected host correctly. The spawn verification fixture uses a seed appropriate to the explicit portable SplitMix64 stream.

The current [host migration feature document](../features/host-migration.md) owns the design details and limitations. The [EOS procedure](../eos-development.md#host-migration-checks) separates local/fake evidence from separate-device service testing.

## Limits and remaining uncertainty

- No real EOS-connected multi-PC migration, residential NAT/path test, live Locked migration, changed-network former-host restart, or service ownership-notification timing was observed. These remain separate-device acceptance evidence to collect when available.
- Migration requires at least two eligible survivors and unanimous agreement among the retained eligible roster. Multiple simultaneous failures may deliberately fail recovery. A two-player session cannot migrate to its sole survivor.
- Checkpoints are sent every 0.5 seconds; four copies retain approximately 1.5 seconds of boundaries. Selection permits at most 240 simulation ticks of rollback relative to each survivor's observed authoritative state. This is not a wall-clock outage limit or a guarantee that unobserved in-flight state is lossless.
- Default unexpected-loss grace is 30 seconds and agreement is bounded to 20 seconds. Native migration fixtures shorten grace to three seconds; fake-framing tests exercise the default policy.
- The 64,000-byte checkpoint ceiling and acknowledgement lease deliberately stop unsafe continuation when no recent complete state can be retained. Worst-case long-session history, frame cost and eight-player Internet bandwidth have not been profiled.
- Rollback discards post-boundary outcomes. Restored committed state does not replay historical presentation events or add discarded score deltas to restored totals. Presentation-only effects/UI/audio are rebuilt from current authoritative state.
- EOS metadata/promotions are asynchronous and use operation-generation guards/retry for reported failures. Local evidence cannot prove live service liveness or timing.

## Runtime findings

VERIFIED by scripted production runtime execution:

- Both adapters reached 2.8/2.4/3.6 rad/s for pitch/yaw/roll. Simultaneous pitch+roll reached vector magnitude 4.561 rad/s.
- Sustained roll accumulated 10.014 radians during held input, exceeding a full revolution. Release then reduced speed below 0.02 rad/s without choosing wheels-down.
- Late released attitude drift was at most 0.0007 radians in sampled free-flight cases. Native rendered combined-rotation capture visibly retained a tilted attitude; corrective landing capture was wheels-down.
- Crooked initial spin was damped; explicit test-pilot pitch/roll and yaw corrections prepared landings through both adapters. Corrective test pilots exist only in verification code.
- Repeated-launch fixtures observed four distinct landings per adapter and cleared air continuation on support.
- Authored west jump targets 14/16/18 produced approximately 0.53/0.93/1.27-second flights with 1000 HP after the route driver released pedals in flight. East corridor also passed its assertions.
- Existing driving, suspension, collision, camera, Configs persistence, multiplayer and reconnect regressions passed as listed above.

Core tests separately verify continuous-delay reset, signed chassis axes, disabling stabilization, exact snapshot continuation, Air Roll serialization, accepted configuration round-trip, and equal host/predicted airborne state before and after encoded reconstruction. Those deterministic tests are not remote-device playtests.

### What was exercised

- **VERIFIED:** 20 native air-control scenarios, sustained 10.014-radian roll, pitch+roll, explicit crooked/heading corrections, release damping and four repeated landings per adapter; authored west/east jumps; collision/landing regressions; Configs persistence/replication; two-process UDP and reconnect.

- **INFERRED:** These measurements support responsive arcade correction and predictable release. They do not establish subjective fun, physical-controller ergonomics or Internet air-control feel.
- **UNVERIFIED:** Hands-on driving. The Windows capture interface failed during the attempted local-practice session. No physical controller was connected in native input verification. External-peer airborne play and live EOS recovery were not run.

### Finding and recommendation

- **Problem:** The player-facing transition from road throttle to airborne pitch has not been validated hands-on, leaving material uncertainty about perceived responsiveness and learning friction.
- **Evidence:** The old automated route pilot pitched into a damaging landing when it retained throttle; releasing airborne controls fixed the fixture. That demonstrates the new semantics, but the direct desktop capture failure prevented testing how naturally a player manages that transition. Scripted correction pilots cannot substitute for that judgment.
- **Severity:** Medium.
- **Impact:** A player holding W through takeoff now deliberately commands nose-down after 0.15 seconds. The controls satisfy the requested mapping, but comfort, timing and recovery feel remain unaccepted.
- **Suggested improvement:** Conduct a human keyboard/controller session on both authored jumps, including held-W takeoff, deliberate release, yaw correction, Shift roll, combined input, late correction and repeated landings; include an independent remote peer before declaring multiplayer feel accepted. Change defaults only if that evidence identifies a concrete issue.
- **Scope:** In Scope.
- **Corrective Work Type:** No Code Change Required to obtain the missing evidence; any later tuning needs explicit authorization.

**Recommended Next Round:** Human playtest/acceptance first, followed only by specifically authorized tuning or another critique. No polish round was started. The exact 8.0 gate is not met; test count and implementation effort were not used to raise the score.

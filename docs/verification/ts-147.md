## Assumptions, limitations and risks

- Native evidence is scripted, same-machine test exercise; it is not a human-driven competitive match, Internet/NAT session, multi-PC EOS validation, controller ergonomics assessment or long-duration balance/performance soak.
- Placement supports local driveable terrain (normal Y>=0.55), not cliffs or arbitrarily discontinuous ground. Uneven-footprint variation/clearance guards intentionally reject unsupported installation while retaining the item.
- Mine motion uses Core force integration and the existing style of synchronous native collision queries, not a second RigidBody-owned simulation. Replicas present complete reliable state; delayed delivery may cause visible pauses. No additional mine prediction protocol was added.
- Default balance (100HP,24m,24000N.s), 16-mine capacity and long-session network cost require broader playtest judgment. No separate stress/soak result is claimed.
- Recovery tests use fixture state to isolate checkpoint behavior; ordinary remote use, damage and terrain placement are tested independently by the mine harness.
- No new third-party acquisition or Shared layer. Core remains Godot/provider-neutral; Client owns native terrain queries, presentation/audio and reconstructable bodies.

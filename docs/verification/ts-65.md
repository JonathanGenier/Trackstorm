## Result and changed systems

The existing Core lobby/vehicle/match authorities already retain participants and reservations for the arena lifetime, including Finished. The Story extends that architecture rather than creating another history store or changing scoring. Client standings now expose authoritative `Connected`, suppress offline Ping regardless of the diagnostics provider, and dim all five row cells to 55% opacity. Resume restores normal opacity. Core ranking and authoritative totals remain the only source of statistics.

- `code/Client/Hud/MatchStandingsView.cs`, `StandingsRow.cs`, `MatchStandings.cs`: offline projection and native presentation.
- `code/Tests/Matches/RetainedMatchTests.cs`: integrated Core lifecycle coverage for both loss and intentional Leave.
- `code/TransportTests/MatchStandingsTests.cs`: offline leader/winner, stale Ping suppression, same-player row reactivation and rank/totals preservation.
- `code/Client/Verification/ReconnectIntegrationChecks.cs`: extended real-UDP/native harness.
- Feature documents: standings, reconnection, matches and sessions. Historical verification index links this evidence.

## Limits and lifecycle interpretation

**VERIFIED:** deterministic Core and presentation assertions, local real UDP, native Godot rendering, prolonged socket interruption, and separate-process vehicle regression. Active and final offline images were inspected at `.godot/reconnect-checks/offline-active-standings.png` and `offline-final-results.png`.

The reconnect harness supplies a trusted identity seam and authoritative initial-score/Finished fixtures to isolate retention. Actual missile/ram kills were separately exercised by the native match harness; this is not a claim of a single manual end-to-end combat/reconnect playthrough. Its next-generation assertion constructs the new Core authority; the lobby harness separately verifies complete native arena reconstruction.

**UNVERIFIED:** separate-PC authenticated EOS reconnect, changed public IP, application restart and long Internet soak; no physical-controller or manual multiplayer playthrough claim. Local evidence does not establish those conditions.

The existing host Return command is interpreted as leaving the current arena/results lifecycle. It releases disconnected reservations at that boundary; the following Start creates the next match generation. Nothing is cleared merely because the match enters Finished. Lobby behavior, scoring/attribution/target rules and `Client -> Core` ownership are unchanged; no Shared layer, dependencies or assets were added.

The pre-existing staged `export_presets.cfg` version/company/product edits belong to the user and are excluded from this Story's changes. Runtime screenshots/logs remain ignored under `.godot`.

Final inspection confirmed the branch matched freshly fetched `origin/main` before the Story commit; the complete Story diff and new files were reviewed, `git diff --check` passed, affected documentation links resolve, and project references preserve Core independence.

# TS-162 — destructible environment verification

## Scope and integration

Implemented on the existing `ts-162-pg` branch against fetched `origin/main`
`33bc51c` (TS-166 integrated), version 0.1.58. Jira was read in full and re-read
before completion: no children/comments; TS-161 and TS-166 dependencies Done;
TS-163 is the downstream integrated driving Story. The user authorized commit
and push only, without a PR or merge.

- Core match authority covers 147 rocks and 2,447 soft plants. Static rocks take
  severity-gated native vehicle contacts and committed Missile/Salvo explosion
  damage. Thresholds are 180 then 60; one accepted batch cannot skip a stage.
  Final pieces reuse the smallest authored BoulderLow scale. Existing smallest
  loose stones start final.
- One controlled piece per broken rock, at most 16 moving, maximum 6 m/s and
  eight metres displacement. Simple wheel-only support excludes rigid chassis
  collision; a separate weapon-query shape follows the mesh. No free debris
  bodies or runtime fracturing. Plants flatten for nine ticks then clear using
  bounded batch updates. Authored-buffer reseeding supports native reset.
- Complete bounded environment publications and version-three resume checkpoints
  carry stages, partial damage, cooldown, motion and plant bits through existing
  admission, reconnect and migration. A full-state heartbeat recovers dropped
  terminal publications. New match/practice reset restores authored state.
- Both kicker lips are filled in the existing continuous terrain mesh. Takeoff
  faces at/beyond |x|=83 and the 6.35 m tabletop height remain unchanged. Fill is
  restricted to 70 <= |x| < 83, |z| < 28.25 and only adds material. Blender source,
  runtime GLB and provenance manifests were regenerated.

Structural terrain, track, bridge/tunnel, barriers, drains and poles are excluded.
The unreachable exterior conifer forest remains scenery outside containment.
No third-party assets/dependencies were introduced. Existing user changes to
`InputButtons.cs` and ten untracked stone textures were preserved and excluded.

- Native driving exposed remaining chassis contacts after a swap: both collider
  layer and mask are now disabled.

  bounded fill passed the direct transition, deck and jump cases.
- Native reset exposed cleared MultiMesh instances failing to restore through

  the full rendered reset suite passes. Normal clearing uploads each dirty batch

  all MultiMesh data; headless runs are not visual plant evidence.
- Migration admission was intermittent both during concurrent work and on an
  isolated attempt. Instrumentation subsequently passed without any checkpoint

- The first final `check.ps1` attempt failed with NU1900 while NuGet vulnerability

  --no-http-cache` succeeded; the original gate was rerun without disabling audit
  or weakening warnings-as-errors.

## Limitations and unresolved observations

**Migration admission risk:** repeated three-peer runs sometimes timed out at
stage 61 with `authority fencing could not be established`, before the environment
recovery assertions. Other runs completed exact restoration. Preparation stalls
relative to the existing two-second host-silence policy are a possible factor,
but the root cause is **unverified**. The successful run is not evidence that this
intermittent failure has been fixed. No timeout/authority policy redesign was made.

The broad `-Case Tabletop` run failed `TabletopSide-1_-1` on a damaging contact
near (-38.34, 1.21, -33.33), HP 986.90. That route passes an intact authored rock
near (-41.36, -0.10, -33.81), outside the edited lip region. This run is **not**
reported as passing. Direct lip/deck/jump cases passed. No baseline execution
proved the broad failure predates this Story; integrated route tuning remains a
TS-163 consideration. No unrelated rock relocation or vehicle tuning was made.

Controlled horizontal motion trades free-body realism for safe bounded response.
Mesh swaps are abrupt, with no added fracture VFX or dedicated rock-break audio.
There is one smaller reusable piece, not a fragment cloud. Matching-build scene
ordering supplies stable identities.

### Recommendation 1 — migration admission reliability

- **Problem:** three-peer arena admission sometimes enters an unrecoverable
  authority-fencing failure before the recovery scenario can start.
- **Evidence:** repeated stage-61 failures, including an isolated run, versus
  subsequent successful instrumented restoration. The final gate does not erase
  those failed native runs.
- **Severity:** High.
- **Impact:** players can lose session entry even though the environment checkpoint
  itself is restorable; multiplayer readiness is not established reliably.
- **Suggested improvement:** reproduce with monotonic entry/heartbeat timing,
  compare unchanged main under the same fixture, identify the admission boundary
  that stops progress, then correct the responsible entry path and repeatedly
  exercise two/three peers without weakening authority fencing or timeouts.
- **Scope:** In Scope for the Story's multiplayer/recovery acceptance; no wider
  network redesign is recommended without evidence.
- **Corrective Work Type:** Existing Task (TS-162 Story).

### Recommendation 2 — stage feedback

- **Problem:** the visible large-to-small swap is abrupt and weakly communicates
  a fracture, particularly compared with the scale of the original obstacle.
- **Evidence:** viewed production rock impact captures and controlled stage swaps.
- **Severity:** Low.
- **Impact:** the result reads more like an obstacle disappearing than breaking.
- **Suggested improvement:** a short bounded impact/fracture cue using existing
  presentation assets, while retaining one controlled piece and current collision.
- **Scope:** In Scope polish; optional relative to the admission reliability issue.
- **Corrective Work Type:** Existing Task (TS-162 Story).

**Recommended Next Round:** resolve and re-exercise migration admission first;
consider stage feedback only after that. No corrective round or Jira change was
started after this critique. The user's explicit instruction to commit/push and

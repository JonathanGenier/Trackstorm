## Implemented

- Reused existing flight/terrain/presentation controls and the existing three-round
  magazine, target acquisition, attachment, counterplay, configuration and replication owners.
- Added four host-validated settings in **EMP Claw effect and counterplay**:
  attachment duration (0.1–30 seconds, default 30), nonstacking engine/reverse/Nitro
  suppression (0–0.8, default 0.8), attached membrane radius (0.05–0.3 m,
  default 0.195), and stored membrane radius (0.025–0.12 m, default 0.075).
  New attachments capture their own deadline; edits never refresh existing deadlines.
  Suppression and membrane-query edits apply live through their existing owners.
- Added bounded device-local shockwave scale, electric trail length/intensity,
  impact/pop intensity, deflation and cleanup controls. Immediate session-only controls
  have a local reset; terminal timings are captured at removal. Fixed render budgets remain.
- Added a shared HUD EMP panel with independent accepted countdowns and stable labels,
  surviving-claw state after one removal, brief removal/final-clear feedback, and
  session/life/death/unavailable-state cleanup. New attachments clear stale removal feedback.
  The panel uses accepted host ticks and has a minimum readable scale and dark backing.
- Verified existing physical-slot ammo display 3 → 2 → 1 → Empty, selection and replacement.
  No new ammunition or rack authority was introduced.
- Updated configuration TC55 (284 values / 2293 bytes), movement v15 (181 bytes),
  item TI32 and compatible discovery bucket `trackstorm-lobby-24` for the new wire state.
  Story/build version files were deliberately unchanged per the explicit prompt.
- Updated relevant EMP, HUD and Developer Options feature documentation and this evidence index.

## Runtime evidence and limitations

**VERIFIED:** Scripted native production controls and renderers, actual VFX parameter
changes, normal pickup/use and rack lifecycle checks, three local UDP peers with
100 ms delay / 15 ms jitter / 3% loss, accepted configuration replication, independent
attachment expiry/removal, default nonstacking power, native counterplay and cleanup.
Rendered DevTools, three-claw HUD, partial removal and driving-distance electricity
captures were directly inspected. Final HUD captures show readable text without
clipping or overlap with the bottom instruments at the checked resolutions.

**VERIFIED (deterministic):** Nondefault suppression changes actual Nitro force;
nondefault duration affects new attachments while old deadlines survive; membrane
radius changes alter actual gun hits; all new config values serialize and reject invalid
transactions; HUD session/life/new-attachment boundaries prevent stale feedback.

**INFERRED:** Consistent player-facing HUD during an actual Internet match follows from
separately verified accepted-state projection and peer state/configuration delivery.
The native HUD fixture supplies explicit accepted states rather than conducting a
human match with the production bootstrap HUD visible on every remote peer.

**UNVERIFIED / TS-301:** Authenticated EOS or separate-PC/Internet play, comprehensive
reconnect/latency acceptance, exported-build acceptance, extended sustained-load play,
final balance, listening/audio judgment and human gameplay signoff. The local native
harnesses use explicit poses/input fixtures where documented; they are not human driving.

The prompt's “one chambered, two stored” wording is treated as three total available
rounds for HUD purposes. Existing TS-299 intentionally exposes all three physical noses
and parks the loader; no hidden chamber or model redesign was introduced. Radius tuning
changes query envelopes, not authored balloon mesh dimensions. Three rounds, permanent
captured target identity, one-hit zero-damage pop and the 80% maximum remain invariants,
with explanatory UI text rather than toggles that would violate existing contracts.

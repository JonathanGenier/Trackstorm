## Implementation and Arena Tools inventory

`code/Client/Statistics/` contains the full-screen native UI and read-only category
projections. The bootstrap composes it with the existing session/practice owners;
the existing settings menu suspends navigation while covered. No Core, protocol,
authority, gameplay settings or Dev Mode action implementation changed.

The [feature document](../features/statistics.md) records each data owner, category,
unavailable-value rule and future integration contract. It also inventories the
old Arena Tools controls from the pre-TS-38 source and their current destinations:

- HP, support/surface, handling, player count/role and network timing/correction
  diagnostics are exposed by F2 for the selected entity where supported.
- Held-item state remains in the HUD and is also visible in F2.
- Reset/Detonate, host Give Item and capability-gated network simulation remain in
  the existing Developer Options architecture.
- The duplicate Use Item button was already retired; normal gameplay input owns use.
- Arena Tools UI/toggle was already removed by TS-38. No supported fallback or
  Arena-Tools-only resource remains to delete or reintroduce.

## Failed attempts and limitations

Headless Menu completed all 60 behavioral assertions but its strict wrapper failed
on audio ObjectDB/resource teardown diagnostics. A separate clean clone of unchanged
main (`6bb3237`, with the pinned EOS SDK prerequisite) reproduced this failure:
46 leaked instances and four audio resources still in use. The rendered Menu run
passes. This is a pre-existing baseline limitation, not a Statistic Panel UI leak.

The headless reconnect attempt also completed its behavioral checks but failed on
40 leaked instances/two audio resources at exit. A baseline reconnect attempt
passed, so that specific failure is not established as consistently reproducible;
the rendered TS-58 reconnect run passes. No unrelated audio changes were made to
mask either warning.

The initial Release verification attempts exposed harness issues: Windows GUI
exports return no console output and require explicit process waiting/log files;
the default Release template forbids command-line scene overrides. The final
harness uses an explicit log file and awaited process. Its reserved verification
argument replaces the main scene before constructing its test bootstrap, ensuring
that only one input owner exists. The final exported run passes including teardown.

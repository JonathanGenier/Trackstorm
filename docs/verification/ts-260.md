# TS-260 verification

## Investigation and original state

TS-260 started from `ts-260-pg` at `d25be1e`, identical to `main` and
`origin/main`. The reported Chinese/Korean/garbled root directories were not
present when this work began. PowerShell `Get-ChildItem -Force`, .NET
`Directory.EnumerateFileSystemEntries`, and `cmd /d /c "dir /a /b"` independently
reported the same 90 root entries, all intentional tracked roots plus `.git` and
the ignored `.godot` cache. Enumerating every root name as Unicode code points
found no non-ASCII name.

`git status --short --untracked-files=all --ignored` reported no unexpected root
entry. The only non-ignored pre-existing working-tree change was
`assets/maps/oval/grass_variation.png.import`; it was not modified or included in
TS-260. `git log --all --name-only` found no non-ASCII tracked path in reachable
history. Therefore the reported directories were not tracked in the current tree
or any reachable commit, but their exact former Git ignored/untracked state cannot
be recovered after their disappearance.

The original directory names and contents were not available to inspect, so no
directory was classified or deleted by this implementation. In particular, this
report does not infer names, contents, provenance, or security significance from
the user's description alone.

## Cause analysis

The active car workflow was inspected in `ExportCar.py` and `AuditCar.py`, along
with the historical rebuild scripts, retained Blender source, vehicle authoring
documentation, TS-259 evidence, and asset manifest. The active exporter opens the
constant retained source `assets/vehicles/source/TrackstormCar.blend` and writes
the constant `assets/vehicles/TrackstormCar.glb`. The audit opens that same source
and its only directory creation is the constant ignored evidence directory
`.godot/ts259-round8`. It does not derive filesystem names from Blender objects,
user text, decoded bytes, locale, or command output.

Before any TS-260 implementation change, the documented Blender 5.2.2 export and
audit were executed from the repository root with a before/after root snapshot.
Both completed, the Blender audit passed, the root count remained 90, and no root
entry was added or removed. The exported GLB hash changed despite identical
source, so the test-generated binary was restored to its original tracked bytes;
no generated GLB change is part of TS-260.

No reproducible in-repository path, naming, Unicode, or encoding defect was found.
The most specific supportable conclusion is that the current tracked car scripts
did not create the reported artifacts in reproduction. The historical external
command or process that created already-absent untracked/ignored entries remains
unknown.

## Implemented prevention

- `ExportCar.py` now verifies the Trackstorm repository marker, resolves its
  source/output paths, and rejects any source or GLB destination outside the
  intentional vehicle asset directories.
- `AuditCar.py` now performs the same repository/source validation and rejects an
  audit output outside the repository's ignored `.godot` evidence tree.
- `tools/run-car-blender-workflow.ps1` is the documented export/audit entry point.
  It uses absolute script paths and Blender's nonzero Python exit behavior, records
  the root before execution, and fails if any root entry is added or removed.
- `tools/check-root-artifacts.ps1` derives intentional root names from Git plus
  `.git`/`.godot`, preserves Unicode code points, Git status, and a bounded content
  listing for unexpected entries, and deliberately never deletes evidence.
- `tools/test-root-artifacts.ps1` proves the checker accepts the clean root,
  rejects a temporary unexpected directory, preserves its payload for inspection,
  and passes again after the test fixture is removed.
- `assets/vehicles/README.md` documents the guarded workflow, and
  `car-sources.json` records the changed active Python script hashes.
- The normal Story version was synchronized from main `0.2.3` to `0.2.4`, with
  Windows export versions `0.2.4.0`.

## Assumptions and limitations

- The user-observed directories existed before this checkout state, but their
  names, timestamps, contents, and filesystem metadata were unavailable at the
  start of investigation.
- Reachable Git history can establish that no non-ASCII path was tracked there;
  it cannot distinguish an already-removed ignored entry from an already-removed
  ordinary untracked entry.
- The root guard detects and reports creation after it occurs; it intentionally
  does not delete or quarantine an unknown entry. The Python assertions prevent
  the active scripts' known outputs from escaping their intended directories.
- Blender GLB export was not byte-deterministic in this environment. Because
  model content was out of TS-260 scope, each test export was restored to the
  original tracked GLB rather than committed.
- NuGet's vulnerability endpoint was unavailable. Compilation/tests passed with
  `NuGetAudit=false`; dependency-vulnerability freshness was not established.

## Jira preservation method

All 55 visible TS issues were inspected individually with all 32 available comments; comment totals matched returned counts and project search pagination was exhausted. No Bugs were present in this inventory.

51 descriptions were edited using explicit issue/node selections, not keyword deletion. Before each write, description and comment content were fetched again and compared with the audited version. ADF edits preserved unchanged nodes, formatting, source links and technical content. Mixed process/feature sentences retained their feature-specific verification or documentation obligation. Obsolete monolith targets became feature-documentation wording without dropping required documentation content.

A final fresh read of all 55 issues exactly matched every intended ADF description. All fetched non-description fields (summary, status, type, parent, issue links, attachments and full comments) matched their pre-edit values. The only unique links removed from description link sets were TS-45 and TS-46 self-links in deleted Git boilerplate; no dependency or asset-source link was lost.

Before/after snapshots, explicit edit plans and change accounting are retained locally under ignored `.godot/ts56-audit/`: `jira-before.json`, `jira-edit-plan.json`, `jira-prepared.json`, `jira-after.json` and `jira-written.json`. These are audit evidence, not current requirements. Raw Jira copies were not added to source control.

Generic categories removed: obsolete Git/branch/PR procedure, generic build/format/test commands, generic architecture/routing instructions, Codex/Astra labels, generic self-critique/completion instructions and generic feature-document maintenance. Architecture requirements defining the actual feature (especially TS-1/TS-2 and EOS/provider boundaries) remain. Comments were preserved as historical requirement clarifications.

## Changes

- Expanded native UDP profiles with 25 ms outbound delay / 5 ms jitter and eight-player combined delay, jitter, loss and reordering.

- A separate eight-player delay/jitter/reordering test withholds every fiftieth ordinary received snapshot before the driver, with native loss disabled. This controlled application-loss seam has an observable drop count. The initial runs combined this seam with native loss; that stronger stress condition is explicitly recorded below. - Added an explicit ten-minute native eight-player movement soak and `check-network-soak.ps1`, followed by fifty impaired production rematches. Added bounded-history/reset assertions and per-cycle managed/native resource and event-journal measurements to the existing post-match harness.

- Corrected the authenticated EOS smoke fixture to advance on physics ticks and wait for synchronized Active gameplay before twenty active steps and Return. Added credential-safe failure-stage diagnostics; the original twenty-render-frame assumption did not honor asynchronous match loading.

There were 79,027 accepted snapshots, 20,198 delivered stale probes individually rejected without authority replacement, and 1,609 controlled snapshot drops. In-loop failure and snapshot-history checks ran throughout; final convergence/correction assertions after the first failing hold assertion were not reached in this attempt.

Minute-level process private bytes ranged 34,668,544–38,473,728, working set 93,925,376–97,521,664, handles 447–452 and managed memory 3,500,032–14,321,464. These fluctuating totals include NUnit, correction-sample lists and runtime allocation/collection; they do not isolate a networking leak. The data does not show a monotonic pending-input or snapshot-age backlog. It does expose brief operation of the existing eighteen-command prediction limit.

The first runner stopped before rematches after that failure. The fifty-cycle rematch check was therefore launched independently. ## Final acceptance status and remaining limits

**TS-121 is not accepted as complete.** The validation tooling/evidence is deliverable, but mandatory gameplay-vote coverage is blocked by TS-188 and the nominal long movement soak fails two unchanged quality assertions. Jira remains authoritative; no requirement was removed or Story closed.

- **VERIFIED:** representative local UDP profiles, separately counted delivered stale rejection and controlled unreliable loss, eight-player state/traffic scenarios, repeated native rematch cleanup, local late join/reconnect/migration, item/Circus/final-result behavior and bounded observable histories/journals described above.
- **INFERRED:** the stable rematch node/object counts and bounded histories argue against accumulation in those owners over this run. They do not attribute all process memory growth or prove every publication/native send queue stays bounded under saturation.
- **UNVERIFIED / BLOCKED:** Vote Kick, Vote Pause/Resume, paused admission and active Resume electorate changes, including repeated voting. Their owning implementation is absent. This is an existing-Story dependency, not permission to build voting here.
- **UNVERIFIED:** real separate physical PCs, distinct authenticated identities across residential networks, NAT/relay diversity, remote EOS packet delivery/reconnect/migration, exported-build WAN runs and live multi-PC lease behavior. No second-PC tester or separate-network endpoint was provided during this run. Single-machine local UDP and solo authenticated EOS cannot establish these results.
- **UNVERIFIED:** one sustained all-feature eight-player EOS game combining repeated voting, combat, Oil/Nitro, joins, reconnects, migration and rematch; multi-hour soak; exact native queue bytes/wire retransmission and per-system retained-heap attribution; physical-controller use, audible quality and continuous human-perceived driving smoothness. Short recovery checks and isolated movement/rematch soaks are complementary coverage, not substitutes for that combined session.

The final source review stayed within verification fixtures, scripts, routing, evidence/docs and canonical Story version metadata. No production prediction horizon, item/scoring protocol, gameplay owner or TS-120 publication behavior was changed. The latest fetched main still resolves to the TS-120 merge; version/ancestry checks passed at 0.1.74. The unrelated grass import remains excluded.

# TS-283 verification

## Scope and implementation

Story TS-283 under Epic TS-229, implemented on `ts-283-pg` from current main `73c6811b56cc8ae3b05229d66b7ffdfcb0ab2911` (merged TS-286 / PR #328). Main was fetched again before final verification and had not advanced. Story version is 0.2.34, derived by `tools/sync-story-version.ps1`; Windows metadata is 0.2.34.0. The existing unrelated stashes were not touched.

- Aerial release now multiplies angular velocity by `exp(-AirReleaseDamping * dt)` after player input arms the existing release latch. Default damping is 10/s. At 60 Hz, each step retains 84.6%; 95% settles in about 0.3 s. Full default roll adds roughly 17 degrees of finite residual rotation, rather than freezing instantly or drifting indefinitely. No orientation target, passive-flight braking, gravity/trajectory change or new continuation field was introduced.
- The TS-286 predicate remains intact: every chassis contact cancels assistance, including a damage-forgiving underside contact without wheel support. Existing active input, counter-input, crash latch and wheel recovery remain.
- Rear-quarter contact increases yaw compliance within the existing inelastic impulse calculation. Rear lever, lateral offset, side-facing normal, road speed and relative translational closing speed qualify it. Both masses/wheelbases and contact velocities determine the same equal/opposite impulse. Angular compliance is bounded before the effective-mass solve, preventing a clipped response from leaving artificial closing velocity. No spin command, extra impulse, cooldown or traction-loss timer was added.
- Defaults: PIT closing onset 1.5 m/s (full qualification at 3), qualified yaw multiplier 1, qualified angular-change bound 2.5 rad/s. Ordinary crash response remains the floor; zero PIT limit or a response no greater than ordinary crash rotation disables the additional response. Existing tire forces and steering recover control.
- Practice uses the same Core pair batch as the network host. The corrective round retains complete native observations for connected mixed world/vehicle contacts; pure vehicle-contact groups retain the existing shared PIT input boundary. Prediction still changes only the local body; the host owns pair outcomes and damage. Raw contacts remain available to existing damage handling.
- The existing repeated-rock harness received the same pre-shutdown managed-wrapper drain used by `SurfaceIntegrationChecks`, after two runs passed their gameplay assertions but failed during Godot finalization. No collision assertion or threshold was relaxed.
- Four Developer Config keys use the existing transaction, validation, persistence and authority paths. TC43 carries 226 values / 1829 bytes and rejects old wire layouts. Vehicle snapshot serialization is unchanged.

### Root cause and correction

The original batch rewound every vehicle-contact participant to its prior Core command and accepted effects. It then restored only non-vehicle normal projections, losing the already-observed native tangential and angular changes. Rewinding just the other participant is also unsafe because native pair momentum has already coupled both vehicles.

`VehicleContactBatch` now finds vehicle contact groups. Any group touching the world keeps every participant's complete captured state, including chains and one-sided contact reports. Core's existing `ResolveContacts` then operates on remaining closing motion from that boundary. Already-resolved native pair contacts need no additional impulse; wall/terrain constraints can limit PIT disruption. Unconnected pure vehicle groups retain the full existing shared PIT solve. A full native contact report conservatively preserves the whole batch because omitted world contacts or connecting pairs cannot be ruled out. Environment-only capture, native world semantics, raw damage observations, authority/prediction, configuration, aerial settle and TS-286 cancellation are unchanged. Existing accepted effects are not replayed in mixed groups; newly queued requests continue to the existing Core step.

No environment rule was added or rerun in Core. A diagnostic native probe established that the installed Godot backend reports contact impulses one boundary late (first collision: velocities changed but reported impulse zero; next boundary: prior impulse reported), so subtraction cannot reliably isolate the current pair impulse. The probe and its initial script setup error are local under `.godot/ts-283/round2/native-impulse-probe.gd`. A first trial preserving all native pair results reduced the existing medium PIT peak to 0.4192 rad/s and failed its unchanged 0.5 threshold; it was discarded. The final mixed-group approach preserves the original pure-pair PIT measurements.

# TS-283 verification

## Scope and implementation

Story TS-283 under Epic TS-229, implemented on `ts-283-pg` from current main `73c6811b56cc8ae3b05229d66b7ffdfcb0ab2911` (merged TS-286 / PR #328). Main was fetched again before final verification and had not advanced. Story version is 0.2.34, derived by `tools/sync-story-version.ps1`; Windows metadata is 0.2.34.0. The existing unrelated stashes were not touched.

- Aerial release now multiplies angular velocity by `exp(-AirReleaseDamping * dt)` after player input arms the existing release latch. Default damping is 10/s. At 60 Hz, each step retains 84.6%; 95% settles in about 0.3 s. Full default roll adds roughly 17 degrees of finite residual rotation, rather than freezing instantly or drifting indefinitely. No orientation target, passive-flight braking, gravity/trajectory change or new continuation field was introduced.
- The TS-286 predicate remains intact: every chassis contact cancels assistance, including a damage-forgiving underside contact without wheel support. Existing active input, counter-input, crash latch and wheel recovery remain.
- Rear-quarter contact increases yaw compliance within the existing inelastic impulse calculation. Rear lever, lateral offset, side-facing normal, road speed and relative translational closing speed qualify it. Both masses/wheelbases and contact velocities determine the same equal/opposite impulse. Angular compliance is bounded before the effective-mass solve, preventing a clipped response from leaving artificial closing velocity. No spin command, extra impulse, cooldown or traction-loss timer was added.
- Defaults: PIT closing onset 1.5 m/s (full qualification at 3), qualified yaw multiplier 1, qualified angular-change bound 2.5 rad/s. Ordinary crash response remains the floor; zero PIT limit or a response no greater than ordinary crash rotation disables the additional response. Existing tire forces and steering recover control.
- Practice retains native nonpenetrating poses and uses the same Core pair batch as the network host for participating vehicle momentum. Prediction still changes only the local body; the host owns pair outcomes and damage. Raw contacts remain available to existing damage handling.
- The existing repeated-rock harness received the same pre-shutdown managed-wrapper drain used by `SurfaceIntegrationChecks`, after two runs passed their gameplay assertions but failed during Godot finalization. No collision assertion or threshold was relaxed.
- Four Developer Config keys use the existing transaction, validation, persistence and authority paths. TC43 carries 226 values / 1829 bytes and rejects old wire layouts. Vehicle snapshot serialization is unchanged.

## Runtime critique

Independent Astra Medium Story Round 1 completed after final verification: **8.1 / 10 — PASS**. Full category judgments, direct observations and limitations are preserved in [the formal critique](ts-283-evidence/astra-round1.md).

The reviewer independently ran all 18 PIT cases rendered, all 48 aerial cases rendered, custom aerial/re-input/descent/landing sequences through both adapters, two-peer impaired UDP PIT and four-world rendered following. All review runs passed. The independent following run had 529 close-following frames, zero stopped/backward steps, p95 correction 0.030029 m and maximum 0.056641 m; PIT corrections peaked at 0.1961 / 0.3366 / 0.1980 m. The earlier intermittent failure remains disclosed.

The reviewer directly observed different damage between adapters: high PIT native target/striker HP about 951.33 / 951.33, swept adapter 1000 / 950; medium about 994.12 / 994.12 versus 1000 / 990. Both participants receive physical consequences and authoritative per-vehicle damage agrees across UDP peers. Separate raw contact observations are a possible explanation, but no main-baseline runtime comparison establishes whether the asymmetry is pre-existing. It is recorded as a limitation, not silently treated as a verified regression or equivalence.

No further implementation or polish was applied after the critique. The user's explicit delivery instruction authorizes commit, push and the single Story PR; further improvement work requires human direction.

## Assumptions, limitations and risks

- The production Van is not integrated in current main. Unequal mass/wheelbase fixtures use the Car collision envelope; actual Car/Van and Van/Car geometry, visuals and production selection remain **UNVERIFIED**.
- Rendered observation and synthetic keyboard/controller input do not establish physical-device ergonomics or a human driving judgment. No listening/audio judgment is claimed.
- UDP checks use local processes with artificial impairment, not geographically remote machines or authenticated EOS sessions. Those environments remain **UNVERIFIED**.
- Native rigid-body pose solving and network sweeps differ; shared impulse rules do not promise bit-identical trajectories. The contact solver remains a bounded ordered pair solver, not full-world rollback.
- Config changes are intentionally wire incompatible with TC42, matching the existing whole-catalog compatibility policy.
- PIT strength depends on contact placement, momentum and tire recovery. The exercised contacts recover rather than reliably spinning a target through a large angle. Formal critique must judge whether the observed disruption meets the intended feel.

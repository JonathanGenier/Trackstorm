## Assumptions, limits and unverified behavior

- New ranges are bounded implementation choices because Jira specified safe supported bounds without numbers. Heights use the existing rack-relative camera reference on the vehicle; this retains the exact default lens position.
- Native mouse/gamepad events are synthetic. Physical-controller ergonomics, prolonged human comfort and real-device mouse feel remain **UNVERIFIED**. Scripted launches/targets are fixture-authored; subsequent motion/contacts use production physics.
- Multiplayer evidence is three independent same-machine UDP peers. Real Internet/multi-device/EOS acceptance is **UNVERIFIED**. Host tuning and observer FOV remain unchanged by shooter preferences; resulting camera aim intent intentionally travels through the established aim contract.
- Supported representative low/default/high values were exercised; exhaustive continuous-value combinations are not claimed. Dynamic authority retains rate, pitch, readiness and self-clearance restrictions: the cursor represents view intent, not guaranteed accepted barrel direction or live firing alignment.
- Machine Gun/Missile camera-directed firing integration remains the explicitly documented separate work. This Story verifies shared aiming and preserves existing firing behavior.
- Camera obstruction may constrain selected framing; extreme look angles can crop the followed car. Those existing safety/view tradeoffs remain active.
- Vulnerability audit, exported builds and remote-network tests are unverified. No new dependencies/assets were added.

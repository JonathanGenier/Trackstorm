Scope: [TS-86](https://jonathangenier.atlassian.net/browse/TS-86), including the approved 2026-09-19 browser/admission/joined-Lobby/map-selection update. No subtasks, comments or remote links were present. Prerequisites TS-85, TS-91 and TS-71 were Done. TS-92/TS-93 behavior was not implemented.

Branch: ts-86-jg. Synchronized with main aa05b00 (TS-131). Normal Story version: 0.1.7, Windows metadata 0.1.7.0.

## Application and network changes

- Main Menu opens Lobby Browser over persistent MenuShell media; explicit asynchronous admission precedes a separate joined-Lobby presentation.
- Host-only Core map selection supports exactly Old Map and New Map. Selection travels through complete lobby state, reconnect and migration.
- Match-only threaded resources are separated from startup loading. Native scene construction uses the selected map.
- Initial peers install complete checkpoints and acknowledge synchronization before host tick zero can advance. Clients also require host release before input/prediction entry. TE control is nested in the existing authenticated session/epoch/connection envelope.
- The completed SynchronizedMatchContext reaches TS-91 initialization through Simulation.InitializeMatch. Existing atomic match rules remain the sole continuing phase owner. Active join/reconnect restores current state without restarting the match.
- Bounded loading/sync failure uses existing Leave/cleanup and preserves a frontend diagnostic. TL schema eight / EOS bucket trackstorm-lobby-15 require compatible builds.

- check-migration.ps1 -Players 2 and -Players 3 with application entry enabled: passed sequential authority changes and state continuity.
- git diff --check: no whitespace errors; complete Story diff reviewed against main.

Godot: 4.7.2 .NET on Windows. Runtime logs are ignored artifacts under .godot/ts86-*.log and the normal per-harness evidence directories. Rendered captures inspected: .godot/lobby-checks/3bb1a418712741faa0b2007a1f3cddb7/lobby.png and .godot/online-lobby-checks/browser.png.

Earlier runs exposed and corrected a UI source encoding issue, stale wire-version test fixture, and harness assumptions about immediate gameplay/resync. Startup shutdown now explicitly drains media before the harness exits. One concurrent three-player migration run completed behavior but reported native teardown resources; standalone verbose and final ordinary runs completed cleanly. A reconnect run also completed behavior but failed strict shutdown warning checks; its verbose repeat was clean. The reconnect harness now allows thirty frames instead of four for stopped native arena voices to drain; the final strict check passed without warnings. These intermittent native shutdown observations are retained here rather than treated as proof of a prolonged soak. No real EOS or multi-PC result is inferred from these local runs.

- Separate-PC EOS Public/Locked admission, selected-map start, reconnect/process restart and migration under real service/NAT conditions.
- Audible frontend continuity and subjective interaction quality; rendered UI was inspected, but audio output was not listened to.
- Resource corruption/missing-import fault injection and prolonged network/load soak.
- Dedicated Game Loop phase synchronization and results/reset remain TS-92/TS-93 scope.

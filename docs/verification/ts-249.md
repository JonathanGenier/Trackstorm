# TS-249 — Proxy Mine model and visual design

Verified 2026-09-29 on `ts-249-jg`, version `0.2.8`. Read the complete Jira description, comments, children, links and history: no comments or required children; TS-251 is a separate blocked Story. The user approved the imagegen concept before implementation. Its proportions were compressed to the existing footprint while retaining the armor, coils, circus colors/teeth and protected beacon.

## Implemented

- Original Blender 5.2.2 LTS model, editable master with 120 component meshes, reproducible authoring script, packed original procedural textures, runtime GLB, retained approved concept and checksummed provenance under `assets/items/proxy-mine`.
- The six `ProxyMine_* patina.png` files are Godot's extracted runtime copies of those embedded original textures, retained with the model. Delivery documentation records their derivation; no asset or behavior changed after critique.
- Two exported mesh nodes, six shared body surfaces and a separate beacon lens; 14,861 triangles. Independently reimported bounds: radius 0.648749 m, bottom -0.25 m, top +0.348 m. No collision nodes, animations or external GLB dependencies.
- Existing `ProxyMineVisual` loads the model; the ordinary match loader prepares it. World and existing rack reuse the same visual. Each beacon owns its pulse material. Existing blink timing, red light and committed impact presentation remain.
- Diff against `origin/main` confirmed no changes to Core, authoritative tests, `ProxyMinePhysics`, `ItemPresentation`, `RackItemVisual`, vehicle/rack implementations or networking protocols. Deployment, attraction, contact, damage, knockback, collision and balance remain unchanged. No TS-250 explosion redesign, TS-251 polish implementation or TS-227 Boost change.
- Extended the native mine harness for sixteen ordinary deployments, three-peer agreement, collision-free visuals, shared meshes/independent beacons and chronological production chase-camera captures. Fixture cameras/platforms disable interpolation; production camera/physics behavior is unchanged. Asset-path changes now route to this harness.

## Assumptions and limitations

- The approved concept is art direction, not a new collision envelope. Existing physics has no spin state: movement is sliding/support tilt and gravity, not independent rolling. This is intentionally preserved.
- Godot 4.7.2 .NET, Windows, OpenGL Compatibility, RTX 4070 Ti; scripted native platforms in the prototype arena with the real 65-degree chase camera. Chronological image samples cannot establish absence of every between-frame artifact.
- Existing explosion and large knockback are retained. Explosion redesign, final cross-system polish and long-session balance remain separate scope.

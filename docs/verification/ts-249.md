- Mine sits at full world scale on top of the existing production Car rack. The original Blender arm mounts underneath, reaches over the rear edge, grips, lifts, lowers, releases and folds back underneath. The Car master and runtime Car model were not changed.
- Retained approved arm reference, editable Blender master, builder, portable GLB and five original extracted patina maps. Independent audit reopened **97 editable components**, checked **14 asset hashes**, and reimported **8 rigid meshes / 15,228 triangles / 30 material surfaces**, with five packed maps and required pivots. - Existing `RackItemVisual`/`CarRackPresentation` owns `ProxyMineRack`; existing `ItemPresentation` creates only released world mines. There is no arm collider or duplicate inventory. The same full-size mine geometry crosses the visual handoff without a scale change.
- Accepted use consumes the item at cycle start. Existing host item state now carries placement life and remaining ticks through item protocol **14** and existing checkpoints. Normal placement takes **180 ticks / 3 s**, followed by the unchanged ground-hazard rules and seating period. The empty arm's return is **0.70 s**.
- A carried mine reserves capacity but has no attraction/contact/damage. Initial invalid/unreachable placement retains the item. Loss of support during an accepted cycle holds/retracts the carried mine and requires the final **50 lowering ticks** with valid support before release. The physical reach is **3.5 m**. These are implementation choices for the approved actual-placement requirement, not post-release balance changes.
- One accepted placement per car; a busy-arm mine request retains its capability. Death/reset/permanent departure cancel carried mines; released mines retain their prior persistence. Switching does not cancel placement, and the rack finishes that action before showing the latest selection. Other item authority rules remain unchanged.

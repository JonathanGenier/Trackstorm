## Implementation

`PlayerInput` owns all production Godot mouse-mode writes. The bootstrap supplies arena presence, while the adapter's existing focus and gameplay/diagnostic suppression gates notify the owner synchronously. Frame callbacks reconcile session transitions. Unsuppressed focused gameplay uses `Captured`; menus, loss of focus and teardown use `Visible`. Menus retain pointer availability during controller navigation without introducing a device-mode system or changing logical bindings, menu navigation, camera behavior or simulation timing.

Changed implementation: `code/Client/Input/PlayerInput.cs`, `code/Client/Input/PlayerInputAdapter.cs`, `code/Client/Bootstrap/SimulationBootstrap.cs`. Extended existing `InputIntegrationChecks.cs` and `MenuIntegrationChecks.cs`. Updated the input, Game Menu and Settings feature documentation and this evidence index/report.

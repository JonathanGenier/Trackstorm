- Bound speculative movement and replay to 18 commands (300 ms at 60 Hz). Continue retaining/sending controls within the existing 120-command transport history. Prediction holds during longer acknowledgement outages and resumes on authority progress. This trades speculative runaway for an explicit responsiveness limit during severe stalls.

- Target one snapshot interval (50 ms) of remote buffering on stable delivery, adding up to another interval for measured arrival variation. Preserve monotonic interpolation/endpoint holding. - Extend existing Stats with constant-space startup/steady correction buckets, maximum, pending commands and prediction-hold state. Extend verification with distributions, correction rates, hard-snap phases, buffered/received-timeline delay, RTT, ack progress and frame/step timings. No per-packet gameplay logging, blocking networking or unbounded production cache was added.
- Add regression coverage for exact confirmation versus replay, host health/impulses, bounded prediction/recovery, reliable boundaries within snapshot bursts, stale/reordered traffic, low-delay continuous presentation and clock recovery. Clients drive for 16 simulated seconds: acceleration, inward steering, drift, braking/settling. Host duration is 24 seconds. The Godot fixture adapts steering/throttle to current orientation/speed, so startup differences can change the subsequent path and native contact/query cost; it is not a replay of an identical input trace. The native Core/driver fixture also changes steering repeatedly over 720 ticks. Startup is the first two **simulation** seconds after roster readiness; later samples are labeled steady. Initial convergence can extend beyond this cut with eight cold processes. Production Stats uses its first 120 local prediction steps. Neither split proves lifecycle causation.

Error is old versus reconciled present prediction after replay, not raw distance to a delayed host. Hard snaps count actual smoothing resets: accumulated offsets can exceed 3 m even when each correction is smaller. Baseline snaps were total-only; completed data splits phases. Baseline immediate-input counts only proved history progress; completed counts also require predicted-tick progress without a new acknowledgement.

**Delay caveat:** baseline latest-tick-minus-cursor values can overstate actual presentation age because sampling clamps an out-of-history cursor to the oldest retained endpoint. Multi-second values establish broken clock recovery, not measured multi-second visual latency. Baseline actual clamped sample age was not recorded. Completed buffering measures a cursor inside retained data. Received-timeline delay adds snapshot age; neither includes unknown one-way transit. Half RTT is only a symmetric-path estimate. Fixed-step metrics can repeat the last presentation sample while a process stalls.

## Startup and contact characterization

## Acceptance assessment

The implementation materially improves the measured normal-WAN case, but TS-69's complete experiential acceptance is **not established**. Two-player native/headless 60 ms responsiveness and steady hard-snap criteria pass in the measured runs; rendered motion has a larger correction tail. The cold-start criterion remains a quality gap: remaining snaps have no intentional lifecycle cause. Interpolation's fixed-delay/recovery behavior is improved, with the baseline sampled-age limitation stated above. Approximately 100 ms/jitter and 2% loss remain functional and bounded in these finite tests. Eight-player impairment is functional but falls short of a polished synchronization experience. Session/combat/recovery checks pass with the documented fixture repairs. Authenticated EOS verification failed; real two-PC testing is unavailable. Jira was not marked complete.

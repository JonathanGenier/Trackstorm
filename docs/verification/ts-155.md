Date: 2026-09-25 (America/Toronto). Branch: `ts-155-jg`. Jira TS-155 was read in full, including all fields, its empty comments and empty subtask list. No requirement changes were made. ## Implemented

- The existing atomic `MatchAuthority` applied-damage loop now awards registered item damage through `CircusScoring.Bank`. Straight Missile, Proxy Mine, Salvo and Machine Gun register their existing authoritative source identities. No weapon awards points itself and no client score authority was added.
- Base points use actual HP removed, including fractional loss and overkill clamping, multiplied by the attacker's current authoritative K/D. Self, zero-applied, unknown/unattributed and missing-score-owner damage earns no offensive award. Distinct hits and targets score independently; existing victim/life/sequence watermarks consume duplicate outcomes and inactive-phase outcomes.
- Damage awards precede the victim's separate existing kill award. Kill attribution, K/D rules, timed Circus completion and FirstToTarget behavior remain owned by their existing authorities. Persistent mines can award a retained owner's score row after vehicle removal; kill eligibility remains unchanged.
- `match.item_points_per_damage` defaults to 1, is finite and bounded to 0–1,000,000, and uses ordinary host-only live configuration, schema-two persistence and complete recovery. Zero disables item-damage contribution while preserving kill points. The default is an initial balance assumption, not a competitive balance finding.
- `ItemDamage` is a category in the existing banked total/award publication and HUD feedback. Match wire version 9 allows 112 bounded award rows; configuration version 22 carries 167 keys. Complete join, resume and migration retain totals, watermarks and tuning without replaying historical awards.
- Focused tests cover all four damage identities, fractional K/D, overkill, zero/rounding-to-zero damage, invalid/self attribution, multiple hits/targets, duplicate identities, new lives, removed owners, inactive/Finished/FirstToTarget behavior, zero conversion, tuning validation/persistence, full bounded codec payloads, join preview and continued scoring after authority restoration.

## Iteration findings

Initial deterministic runs exposed old assertions that item damage earned zero points or that a lethal item only earned kill points. These expectations were updated, including the native Machine Gun and three-generation results fixtures. Early test setup errors (invalid synthetic life/history and nullable fixture state) were corrected before passing verification.

An initial rendered Salvo run sampled a marker in the same frame inventory changed. Its fixture now waits for the marker's presentation update. A concurrent rendered rerun timed out before firing; isolated headless and rendered runs then passed. The Salvo positioning fixture now preserves existing damage sequence memory while refilling HP, avoiding an artificial replay of sequence one. The initial migration fixture captured its expected configuration before the new live rate edit; it now captures the actual host configuration after the edit. An initial sandbox restore cached a NuGet audit warning; an authorized full network restore cleared it. Final build logs have zero warnings/errors.

## Assumptions, limitations and unverified areas

- VERIFIED: deterministic authoritative behavior; local native UDP weapon scenarios; configuration UI/persistence; native checkpoint installation; rendered score feedback as described below.
- Recovery fixtures deliberately inject three small authoritative damage effects before capture to isolate score continuation; they do not claim a live projectile struck during authority loss. Existing recovery also retains mine state, partial Salvo ammunition/flying rounds and Machine Gun ammunition. Continued post-restore damage scoring is covered by deterministic host-authority tests.
- UNVERIFIED: authenticated multi-PC EOS, independent-device WAN behavior, human keyboard/controller ergonomics, audio listening, competitive balance, prolonged soak/performance measurements and arbitrary terrain. Three-peer migration was exercised here; a separate two-peer native migration run was not performed for TS-155.
- Native visual checks use controlled arena geometry and scripted input. Screenshots are direct rendered evidence, not a human multiplayer match or complete HUD redesign review.
- Existing selected-checkpoint rollback semantics still apply to score/tuning on migration. No stronger persistence guarantee or cross-platform native physics determinism is claimed.
- No dependencies/assets were added. Production ownership remains Client -> Core, without a Shared layer. The pre-existing `assets/maps/oval/grass_variation.png.import` edit is excluded from TS-155 commits.

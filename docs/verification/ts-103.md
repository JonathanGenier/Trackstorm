## Tuning and completion decisions

These fill Jira's intentionally configurable balance/definition details; they are implementation assumptions, not a human balance sign-off.

- Drift: existing physical sliding, upright chassis, at least 5 m/s; 0.25 seconds uninterrupted to qualify. Supported upright exit banks; loss of support/inverted exit cancels this category.
- Airtime: previously supported departure, at least 0.25 seconds; living upright landing banks. An untracked airborne spawn cannot arm a flight.
- Drift/Airtime rates independently start at 5 base points/s, add 5 every 2 uninterrupted seconds, cap at four additional tiers (25 points/s). Qualification/rates/interval/step/cap are host tunable.
- Long Jump: 2 base points per horizontal metre between takeoff and landing, not integrated travel or flight duration. The landing interval is included. Returning to takeoff gives zero distance award.
- Top Speed: fixed 5 base points/s; enter at 95% and remain active at or above 92% of configured forward speed (28.5/27.6 m/s for hosted defaults). Vertical velocity cannot qualify; flight and drift may coexist with it.
- Each completion uses the current completion-time shared K/D. Pending projections may change with K/D before banking. Live rate edits affect subsequent accrual; current qualification/thresholds apply next step; Long Jump uses current points/metre at observation/landing.
- Death, reset, permanent vehicle removal and Finished discard outstanding events. Ordinary disconnection retains normal host simulation and its scoring consequences.

## Iteration failures and corrections

- Git initially reported different Windows repository ownership; per-command `safe.directory` was used for this user-assigned checkout. Git metadata fetch/merge required authorized execution.
- Sandboxed Godot initially reported inability to write its user log and read the Windows certificate store. Although scenario assertions completed, that invocation was a failed harness run, not a clean pass. Authorized rerun passed.
- Some sandboxed .NET restore/Client SDK resolutions could not read the installed NuGet configuration. Authorized executions succeeded. The failed `tools/check-fast.ps1 -Area Core` invocation is not counted as a pass.
- Initial broader Client tests exposed two default/dirty assertions for fractional double tuning. The editor previously narrowed all non-integral values to floats. Explicit owning precision fixed the issue, and the full non-native suite passed.
- Initial impaired combat run failed because the old harness compared delayed peer state with the host's newer pending tick; early failure also caused shutdown resource warnings. The harness now validates exact received revisions rather than weakening the pending-state comparison, and the rerun passed cleanly.

## Limitations and explicitly unverified areas

- No separate-PC authenticated EOS, public Internet, exported-build, or full-process gameplay reconnect test is claimed. Native UDP tests and deterministic authenticated-seam recovery are separate evidence.
- Pending stunt continuation through complete restore/rebind is directly tested in Core; the existing native reconnect harness primarily exercises retained banked fixtures, not a deliberately timed interruption in the middle of a stunt.
- No human driving, game-balance sign-off, visual review, audio listening, physical-controller ergonomics or long-session network soak. Circus HUD/ranking/results integration is outside TS-103.
- Stunt native tests use a flat test platform and seeded launch/slide velocities. They do not establish balance across every map/ramp/terrain or the default two-second drift escalation through human controls.
- Binary64 totals have ordinary extreme-value precision limits; native cross-platform bit-identical physics is not promised.
- Active stunts cause complete reliable match publications at up to 60 Hz. The 256-history/eight-pending codec fits below 16 KiB, but maximum-history sustained bandwidth over real Internet connections was not measured. Existing migration checkpoint rollback semantics remain unchanged.
- Independent post-push engineering review and CI are separate gates; no pass is claimed here.

## Delivered behavior and ownership

The production bootstrap supplies arena presence to the existing settings panel, independent of match phase, player count and Force Start. The menu exposes Back to Game, Settings, Leave to Main Menu and Quit. Pure Client `MenuNavigation` owns the contextual back stack; `SettingsPanel.Navigation` routes existing logical bindings; `MenuPresentation` owns artwork and focus styling. Native Controls remain interactive. Only local gameplay input is suppressed; the scene tree and network simulation continue.

The existing `PlayerSettingsController`, settings model/codec/store, `PlayerInputBindings`, audio buses, diagnostics and display confirmation remain authoritative. No settings schema, gameplay action, Core behavior, Shared layer or dependency was added. Leave delegates to `DevelopmentSession.Leave`. Quit and window close wait for the same session/online cleanup before normal tree teardown. Existing reliable departure, transport disposal and EOS shutdown owners remain in place.

**VERIFIED:** A single host entered an arena through the existing Ready/Start lifecycle, remained in `MatchPhase.Waiting`, and opened the menu with native Escape. Escape and Back to Game restored input. Every category opened and returned through Settings; synthetic gamepad Start/A/D-pad/B and a rebound keyboard navigation action worked. Developer content had zero children and only Back was visible as an action. Settings updated the existing model, bus and file. Leave removed the arena and allowed fresh Waiting-state re-entry. Production Quit cleaned the session and exited successfully.

**VERIFIED:** In a second scenario, a real UDP client continued receiving newer snapshots and its vehicle continued moving while the host menu suppressed host input. The same menu opened in Active. Client graceful departure and host Quit used existing session cleanup. The menu never paused the tree.

**VERIFIED:** Rendered captures were inspected for focus, hierarchy, category content and fitting at 640×360, 1280×720, 1920×1080 and 2560×1080. The four Jira references informed dark steel, chains/spikes, carnival canopy/clown and red focus. Existing HUD steel pixels and original procedural geometry were used; no new third-party asset was acquired. The artwork is simpler than the mockups, particularly the clown crest and material detail.

**INFERRED:** Online exit waits on the existing coordinator's membership ownership and exposes retry when cleanup fails. The authenticated service failure/retry sequence was reviewed in code, not exercised against live EOS in this change.

**UNVERIFIED / manual follow-up:** Physical-controller ergonomics, audible volume changes, authenticated EOS sessions across separate PCs, online leave failure/retry and display behavior on other hardware/backends. Synthetic controller events and audio-bus values do not establish those experiences. Existing host behavior closes the session; TS-46 migration is not implemented on this branch and no menu-specific migration was introduced.

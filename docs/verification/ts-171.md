## Implemented

- Circus defaults to 36,000 Active ticks at the established 60 Hz rate. Generic Game Loop state owns Active start, duration and recovery elapsed accounting; initialization/countdown consumes no Active budget.
- Kills never complete Circus. The final Active interval is scored, the existing score-descending / kills-descending / deaths-ascending / PlayerId-ascending ranking chooses the winner, and `GameLoopState.Finish` produces one frozen result. FirstToTarget retains its kill rule. Late outcomes cannot mutate Finished.
- `match.duration_ticks` uses the existing host runtime catalog, validation, Apply/Cancel/Reset, file persistence, reliable configuration and checkpoints. Bounds are 1–216,000 ticks. Live edits preserve elapsed time; shortening below elapsed finishes on the next authoritative step before scoring. Finished edits configure subsequent matches without changing the result.
- Existing top-center HUD displays MM:SS from accepted Game Loop state and authoritative world ticks, rounding up to seconds; default `10:00`, terminal `00:00`. No separate timer UI or local gameplay clock. Practice/FirstToTarget remain `--:--`.
- Match codec v8 and configuration codec v20 carry timer/configuration through admission/resume/migration. The successor debits elapsed time since its retained checkpoint using monotonic receipt age and observed rollback distance. Countdown recovery excludes pre-Active time. A peer that observed Finished refuses an older Active checkpoint.
- Existing Podium handoff, score values, K/D/streak calculations and generic lifecycle ownership remain intact. Current feature docs and native fixtures were synchronized.

## Assumptions, limitations and explicitly unverified areas

- Production uses the established 60 Hz fixed simulation. The full default match was advanced deterministically for 36,000 Active ticks, not played manually for ten real minutes. The native multiplayer expiry uses a shorter host tuning value after six real kills.
- Receipt-based migration timing excludes unknown packet transit before local checkpoint receipt and rounds elapsed recovery down to whole ticks. Observed authoritative rollback distance supplies a lower bound. It prevents reset/lease-wait extension but is not proof of exact wall-clock synchronization under Internet delay or stalled scheduling. Existing coherent checkpoint rollback can discard uncheckpointed scoring; retained authoritative standings are not replayed.
- A Finished observer with no safe Finished checkpoint fails recovery rather than resurrecting Active or changing the winner. This fail-closed branch is covered by fake-provider deterministic tests, not a real EOS outage test.
- Separate-PC authenticated EOS, real service lease/ownership failure timing, changed-network reconnect, long Internet soak/bandwidth, human ten-minute pacing/balance, audio quality and physical-controller ergonomics are **UNVERIFIED**. Local UDP/fake-provider success does not establish these.
- Runtime evidence is automated native operation plus direct screenshot inspection, not a claim of human manual driving. Podium/score balance were not redesigned. No new dependencies or third-party assets.
- CI and independent engineering PR review remain separate delivery gates; no merge is authorized.

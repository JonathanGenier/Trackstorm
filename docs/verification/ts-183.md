# TS-183 verification

## Scope and implementation

Verified against Jira TS-183, including its complete description and empty children/comments/links, on 2026-09-26. No additional approved requirement changes were supplied. Work stays on `ts-183-jg`.

- Admitted hosts and clients edit the same 170-key gameplay catalog. Clients send bounded deltas to the host; Core validates and applies atomic transactions. Gameplay never consumes a speculative client configuration.
- The reliable session configuration channel checks actual transport identity, admission, session, connection generation, authority epoch, match generation, request identity, payload size and catalog values. Complete publications converge lobby replicas; arena configuration still precedes the matching world revision and native/prediction consumers.
- Immediate category/global resets use the same authority path. Pending client requests have explicit confirmation/error feedback. Other peers' changes refresh untouched controls while preserving visible local drafts.
- Late join, existing resume checkpoints and migration restore current shared configuration. Accepted tuning no longer writes participants' permanent defaults files. Existing host seed files remain readable when creating a fresh session.
- Export Changes captures confirmed session values, excludes drafts/local graphics/network simulation, compares against canonical HostedDefaults, groups stable keys by Configs category and includes the actual version plus UTC timestamp. The FileDialog requests native Windows Save As with `configs.txt`; save/cancel/failure callbacks are implemented.
- Force Start, map selection, item grants and local transport simulation retain their existing authority restrictions. No import, admin-permission scheme or defaults promotion was added.
- Canonical version is `0.1.70`; tracked Windows metadata is `0.1.70.0`, derived from current main `0.1.69`. The Story's release target/example is not authorization to change the canonical release prefix.

## Assumptions, limits and risks

- Canonical defaults means `GameplayConfiguration.HostedDefaults`, not a participant's host seed or current session starting values. Exports use stable catalog keys and owning numeric precision; timestamps may differ across separate exports.
- Same-epoch changes are serialized in host receive order; a later edit to the same field wins. Explicit unsaved text is intentionally preserved and remains a draft until submitted/cancelled.
- Existing Core active-match validation remains authoritative for resets. A reset that would change a prohibited match mode or invalid kill target is rejected atomically with feedback.
- A confirmation interrupted by disconnect, timeout or authority change cannot guarantee whether the host applied it. The UI reports uncertainty and instructs checking current values. Migration can roll back to its selected complete checkpoint, consistent with the existing migration contract.
- Local tire graphics/preferences and process-wide transport impairment remain outside shared gameplay state and export.
- The separate-process movement checks passed their existing thresholds but recorded startup/transient corrections: client error p99 was 0.678/0.679 m normally and 0.820/0.638 m under impairment; maxima reached 5.105 m normally and 4.462 m impaired. Impaired client frame maxima were 269/330 ms. This is not evidence of hitch-free rendering or a TS-183-specific performance improvement/regression; those runs were headless.
- No new dependencies/assets or redistribution obligations were introduced. Core remains engine-independent with Client -> Core dependency direction; no Shared layer was added.
- The pre-existing user change to `assets/maps/oval/grass_variation.png.import` is excluded from this Story's commit.

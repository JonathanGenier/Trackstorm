Date: 2026-09-23. Branch: `ts-140-jg`. Synchronized with main `51f8df8` (`0.1.41`); Story version `0.1.42`, Windows preset `0.1.42.0`.

## Scope and implementation

The revised TS-140 Story and TS-145 integration boundary were read from Jira; neither Story has children or comments. Repository workflow, standards, critique, item, pickup, reconnect, and host-migration contracts were reviewed. No additional user-approved requirement changes were supplied.

- The previous TS-140 change generated a fresh seed for each true application match and restored SplitMix64 state inside the flat `ItemSpawnAuthority` selector. This revision retains that fresh-seed lifecycle but makes `HostVehicleSession` own one `ItemSelectionRandom` stream for the match.
- Pickup selection consumes that stream. Its generic positive-bound draw can precede an item draw, so TS-145 can use the same state for category and then item selection. No category selection, credit/deficit state, targets, eligibility, or per-player fairness logic was added.
- The host captures the single stream state with its authority checkpoint and restores it exactly during migration. Ordinary reconnect and late admission retain the running host instance and do not reseed. A true new application match samples a new seed, records it in effective configuration, and starts from that seed. An explicit host Seed edit resets the existing stream; other tuning edits do not.
- Existing weights and registry order, pickup validation/contention/cooldown, item grants and use, and held-slot rules remain in their prior authorities. Explicit selector injection remains a deterministic fixture seam without a portable checkpoint.

These interpretations were surfaced during implementation and documented; they are not represented as new user-approved scope changes.

## Failed attempts and corrections

- A sandboxed build exited unsuccessfully without compiler diagnostics; the permitted elevated build used installed .NET/Godot caches and completed. Initial compile errors in verification fixture construction were corrected before final successful builds.
- First post-match native run rejected an invalid test fixture (kills exceeded recorded deaths). The fixture now satisfies existing Core snapshot invariants. No gameplay validation was weakened.
- An early native run passed 71 behavior assertions but failed strict shutdown validation with two leaked audio objects. Verbose diagnostics identified MP3 stream/playback objects. Production Quit was corrected to keep MenuShell suspended during cleanup; subsequent post-match headless/rendered runs exited cleanly.
- The initial ESC fixture supplied only `PhysicalKeycode`; it was corrected to supply both physical and logical codes, matching native input and existing menu harness conventions. Podium was also placed below the Game Menu/DevTools layers.
- The first rollback fixture incorrectly expected a normal phase publication to undo remote Finished. Existing terminal-publication fencing correctly rejected it. The final test uses local authoritative checkpoint restore and explicitly verifies remote rejection; no network fencing was changed.
- Two startup-only strict runs passed behavior assertions but reported two native audio-object leaks at uncapped headless shutdown. The same native scenario with `--max-fps 60` exited cleanly. The verification script was paced accordingly; the final strict startup check passed. This changes verification timing only.
- An initial menu invocation used unsupported `-NoBuild` and did not run; rerun with supported parameters passed.

## Limitations and explicitly unverified areas

- No separate-PC EOS match/rematch/reconnect, residential NAT, live lease-service failure, whole-process resume, multi-hour soak or TS-121 impairment validation was performed.
- Online membership cleanup failure/retry is integrated with the existing owner and inspected, but no new live service failure was induced from Podium. Generic provider-independent recovery tests passed in the full suite.
- The new native flow harness injects authoritative Finished state to isolate application navigation. Real combat completion was tested separately. The existing native reconnect harness validates driver/checkpoint results retention, not a complete EOS reconnect into the new Podium UI.
- The explicit rollback is a trusted host checkpoint fixture, not proof of live migration during Finished. Existing native migration regression passed separately.
- Native UI button signals and synthetic keyboard input were exercised. Physical controller ergonomics, manual alt-tab behavior, audible mix/loop quality and human gameplay assessment were not performed. Screenshots were visually inspected; no claim of listening to audio is made.
- The generic GdUnit suite, exported executable, cross-platform build and real EOS smoke were not run for this Story. The required root check and relevant native harnesses listed above were run.

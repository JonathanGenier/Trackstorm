# TS-282 — Preserve vehicle aerial inertia through jumps and tumbles

## Scope and implementation

Jira TS-282 was read in full on 2026-10-06. It has no children or comments. Work is on `ts-282-pg`, based on current `origin/main` (`ebd2932b`). No Jira mutation or merge is authorized/performed. The user's delivery instruction explicitly requires commit, push and PR creation after the critique in this run; that overrides the ordinary post-critique delivery stop, without authorizing a new corrective critique round.

- Core accepts aerial input on the first fixed step without tire support, including chassis-only support outside the existing crash latch. Removed the 0.15-second delay.
- Neutral/released axes apply no torque. Linear travel continues with gravity; angular velocity is retained in world space. Yaw-to-roll switching retains existing yaw.
- Held input adds bounded chassis-axis acceleration. Same-direction input never slows faster inherited spin. Opposing input brakes and can reverse rotation; smoothing resets on direction reversal so stale input cannot initially push the wrong way.
- Unsupported crash bounces retain the same inertia as free flight. Existing terrain/obstacle impulses, contact damping, suspension, first-wheel control restoration and delayed crash assistance remain. No new automatic righting or aerial recovery was added.
- Removed obsolete Configs stabilization controls/properties; old saved keys are retained as unknown data but have no effect. Configuration TC42 carries 222 keys / 1797 bytes and rejects older configuration/resume payloads. Existing movement layout retains three reserved legacy stabilization floats; new steps write zero and never apply them as damping.
- Updated Controls guidance, vehicle/input/settings/network/configuration documentation, Core regressions, aerial/landing test pilots and high-spin crash cases. The explicit handling fixture accepts inherited angular velocity and a TS-282 output directory. Canonical/export version is `0.2.32` / `0.2.32.0`.

## Rendered interactive observation

**VERIFIED:** bounded observe/input/observe trials used `handling_playtest.tscn -- --inertia-playtest --handling-flat`, with actual native input capture, rendered frames and per-tick traces. The driver chose follow-up commands from the observed state. This is segmented agent playtesting, not continuous human play.

- Neutral jump: after 60 frames, angular velocity remained zero, horizontal speed remained 12 m/s, and gravity changed vertical speed from +10 to approximately -1 m/s. Subsequent landing was upright with 1000 HP.
- Keyboard barrel roll: reached **3.2368765 rad/s**; 25 released frames retained exactly that speed while the visible vehicle continued through inversion. [Before release](ts-282-evidence/roll-initiate.png), [after release](ts-282-evidence/roll-release.png).
- Deliberate counter-input reversed the roll, then a short opposing pulse reduced it to **0.09607875 rad/s**. The vehicle landed wheels-down with **1000 HP** and resumed powered steering/driving at approximately **24 m/s**. [Landing](ts-282-evidence/corrected-landing.png).
- Keyboard flip: reached **2.5175705 rad/s** and retained it through 30 released frames.
- Inherited multi-axis tumble: angular velocity **(2, -1, 3) rad/s** remained unchanged across 45 neutral airborne frames. [Rendered result](ts-282-evidence/inherited-tumble.png).
- Raw traces are local under `.godot/ts-282/evidence`; [committed summary](ts-282-evidence/playtest-summary.json) preserves first/last observations, frame counts and measured peak spin.

Native crash evidence separately records high-spin side impacts retaining peak rotation **7.73/7.74 rad/s** and approximately **4.97/4.96 rad** total rotation (practice/network). Roof-spin cases retain peak **7.41/4.33 rad/s**, then settle on tires. Multi-flip cases rotate **12.14/11.80 rad**, with seven distinct damaging hits each and final uprightness 1.000. Contact impulses legitimately change spin; the requirement does not imply conservation through dissipative impacts.

## Assumptions, limitations and risks

- The existing crash latch continues to suppress player input until useful wheel support; this Story preserves its inertia and removes ordinary flight's artificial damping rather than replacing crash recovery.
- Existing absolute safety bounds (65 m/s, 8 rad/s) remain. Contact impulses, supported crash damping and suspension still dissipate energy physically/according to existing arcade tuning.
- Aerial control is now available even in short tire gaps. Holding a driving key that maps to an aerial axis can rotate the vehicle during those gaps, as required. Neutral input no longer holds an attitude; players must counter spin.
- Exact build/configuration matching is required. TC41 network configuration and checkpoints embedding it are intentionally incompatible with TC42; saved key-based local preferences retain unrelated overrides.
- No physical controller ergonomics, continuous human trick-driving session, Internet/EOS multi-device play, export, or second-PC acceptance was performed. Synthetic controller events and local native worlds do not prove those outcomes.
- The window-inspection helper did not expose the hidden playtest window; visual observations used the fixture's actual rendered captures. No desktop input was sent to the user's editor or other apps.

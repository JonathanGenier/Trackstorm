## Assumptions, limitations and remaining acceptance

- A host has no upstream connection; its player Ping is unavailable rather than an arbitrary client's latency. Offline Ping reads disconnected. Quality remains null for EOS; GNS may supply its existing fractions. Transport names are forwarded through the neutral interface rather than inferred from SDK types.
- EOS RTT measures application probe round-trip time, including remote polling/frame scheduling. Probes are 25 bytes, at most one per second per connected peer with one outstanding request and a five-second timeout. Replies are limited to two per second. A rejected diagnostic send does not disconnect gameplay. The implementation bounds overhead; no dedicated comparative performance benchmark or long Internet soak was performed.
- Older EOS peers ignore the additive diagnostic frame types and return no sample. Both peers should use this build for acceptance. Host migration and leaderboard presentation are not currently implemented; no such features were added. Existing session/owner replacement rejects old peer data, but an actual migration flow cannot be exercised.
- **Required manual validation remains:** use two distinct EOS PCs/profiles on this build, enable Ping on the client, observe numeric updates in lobby/arena, interrupt connectivity and restore within grace, confirm old latency disappears and fresh latency returns. Repeat across actual session/host replacement. Real EOS remote Ping and Internet reconnect behavior are not established by deterministic datagrams, local UDP or solo authenticated smoke.
- Ready for human review. Final acceptance of the remote EOS criterion remains pending the separate-device check. Jira issues have not been marked Done and no PR has been created.

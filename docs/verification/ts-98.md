## Implementation evidence

- `StatisticPanel` retains the existing capture delegate, 200 ms visible refresh, stable player selection, absent-owner behavior and separate Global/Session and Player/Vehicle views. It fills the shell content area and adds one persistent search field, grouped rows, explicit no-match feedback, white labels and blue (`#69b7ff`) values.
- `StatisticEntry` derives ephemeral display rows from the existing allowlisted compact text, retaining colon-delimited diagnostics, legacy vehicle labels and unlabelled status fragments. Filtering matches category/label/value case-insensitively with trimmed whitespace. A category match reveals the whole category. Native labels display text literally. This adapter neither reads owners nor creates authoritative or replicated state.
- Search changes render the current `StatisticView` without invoking capture. Refresh and player selection still use the original TS-58 data flow. `RuntimeStatistics`, `VehicleStatistics`, `DeveloperDiagnostics`, Core state and network protocols are unchanged.
- The shell opts into ignoring printable keyboard bindings only while Stats search has focus. This prevents P/Pause and remapped menu letters from interrupting text entry. Other binding consumers retain their defaults; direct function keys, Escape, nonprintable keys and controller navigation remain available.
- Feature documentation and the historical verification index were updated. Version metadata follows the repository's normal Story procedure.

## Failures found and resolved during implementation

- Initial sandbox build could not access the user's NuGet configuration; the authorized build outside that sandbox succeeded. Git synchronization likewise required authorized repository access.
- Initial compiler checks identified two StyleCop member-ordering errors; reordered methods and rebuilt successfully.
- Native keyboard testing exposed P closing DevTools while typing. The Stats-specific printable-binding filter fixed this; the final native `hp` check passed.
- The existing menu harness rejected any Stats `LineEdit`; updated it to permit only the presentation search and continue rejecting numeric mutation controls.
- The added remapped-controller fixture initially invoked a remapped button after the harness had restored defaults. Explicitly installing/restoring the test bindings fixed the fixture; the final 756 assertions passed.

## Assumptions and limitations

- **VERIFIED:** current-state diagnostics continue to refresh through existing owners while filtered. Original immutable snapshot tests still cover damage-context/capability-token exclusion, unavailable data, stale inventory lives and deadline projection. The UI has only search, category navigation and player selection; no gameplay/configuration mutation callback was added.
- **INFERRED:** unchanged security allowlisting, reconnect/migration ownership and network protocols preserve their existing behavior. Native evidence exercises same-machine UDP and safe current diagnostic fields, not a new full reconnect or host-election scenario.
- **UNVERIFIED:** a newly exported Release executable, authenticated multi-PC EOS, physical keyboard/controller ergonomics and long-duration performance profiling. Release compilation and deterministic tests are verified; synthetic native input and rendered UI are verified.
- Formatting deliberately adapts the existing safe compact strings. New diagnostic formats should use labelled fields or extend the presentation adapter; unlabelled fragments are retained under State, not discarded or interpreted as new telemetry.
- Force Start remains an existing host-only shared-header action from the approved TS-97 change. It is outside Stats content and was not relocated or modified by TS-98.

### Recommendation and unresolved runtime risk

- **Problem/evidence:** Host footer says “Waiting for everyone to ready up” while seven clients visibly show READY and Start is available. The solo-host capture has the same instruction despite there being no Ready action for the host. The harness successfully starts both conditions.
- **Severity:** Medium. **Impact:** Misleading primary transition guidance can make the host believe another readiness action is required.
- **Suggested improvement:** Show “Ready to start” when all non-hosts are ready (including solo host); otherwise show the unready-player count. Keep Kick guidance secondary.
- **Scope:** In Scope. **Corrective Work Type:** Existing Task.
- **Recommended next round, if authorized:** Correct the guidance, inspect rendered solo/partially-ready/all-ready states, and recheck Start plus ready toggles.

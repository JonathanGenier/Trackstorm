## Implementation and optimization decisions

- Tire feedback reuses one native ray query/exclusion list per vehicle, removes
  temporary wheel-coordinate arrays, and queries water terrain once per sampling
  pass instead of per wheel. The observation order and contact rules remain intact.
- Fully expired track/wake batches now submit zero visible instances. Restart
  reveals only new segments. Per-car storage remains 512 marks, 32 wakes and four
  24-particle emitters; 20 s mark and 0.9 s wake lifetimes are unchanged.
- The imported water plane is cropped from 512 × 256 m to the existing water
  field's wet-texel bounds plus bilinear guard margins. Actual imported area fell
  from 131,072 to 210 m² (99.84% smaller). Original field coordinates, ripple phase,
  shoreline threshold, waterline, collision and immersion sampling are retained.
- Rock/Concrete shared materials replace imported mesh slots, removing unused
  embedded materials/textures beneath overrides. Native map inventory fell from
  40 to 34 material resources and 23 to 13 texture resources. No source image was
  deleted or resized; all remaining map textures are at most 1024 pixels per axis.
- Added a native map-budget inventory and fast-check routing, expiry/restart
  regression assertions, full wet-texel coverage checks and rendered preset
  frame-interval measurements. Updated materially affected feature/authoring docs.

Retained the existing spatial batches, decoration cutoffs, native library LODs,
and static collision strategy. The production inventory contains 260 MultiMesh
batches/3,311 instances (212 distance-limited cover batches), 73 unique meshes,
25 LOD surfaces, 560 collision instances sharing 288 shapes, and 417,772 unique
static concave triangles. The open map has no newly added occlusion volumes.
The precise terrain/oval geometry remains full resolution to preserve wheel,
rim and jump alignment; static collision is not rebuilt at runtime. Unculled
instanced base-triangle totals are inventory, not per-frame submitted geometry.

### Material findings and recommendations

1. **Problem:** eight-process multiplayer driving does not maintain acceptable
   runtime responsiveness and does not consistently complete. **Evidence:**
   three failed stress runs above, large correction distances, multi-second
   frame tails and host acknowledgement/connection errors. **Severity: High.**
   **Impact:** players may see freezes, correction jumps or lost sessions;
   local fixture contention prevents a trustworthy release conclusion.
   **Suggested Improvement:** profile CPU scheduling and native physics/replay
   cost on current main and this branch with the same scenario; repeat with
   peers distributed across independent machines, then fix any demonstrated
   production bottleneck while preserving TS-73 behavior. Do not relax the
   existing convergence gate or reclassify this as optional polish.
   **Scope: In Scope** for TS-83 performance acceptance.
   **Corrective Work Type: New Corrective Task** under this Story if a further
   round is authorized; no Jira issue has been created.
2. **Problem:** direct driving/readability and rendered Configs controller
   interaction could not be fully validated. **Evidence:** desktop capture
   initialization failed twice; visual Configs navigation failed while the
   headless retry passed. **Severity: Medium.** **Impact:** subjective handling,
   dark-preset driving visibility and normal focus/navigation remain uncertain.
   **Suggested Improvement:** perform a focused keyboard/controller drive of
   both loops, water edge and skill pickup under Night/Apocalypse, then change
   presets through the normal Configs UI on a working interactive desktop.
   **Scope: In Scope. Corrective Work Type: No Code Change Required** unless
   that observation demonstrates a specific defect.

# TS-137 verification

## Implemented

- Split Astra critique from independent engineering review: Astra is mandatory where meaningful runtime/player/operational experience exists, while pure repository/process/tooling Stories may rely on operational verification plus independent engineering review when Astra would add no distinct experiential evidence.
- Clarified that independent PR review owns code quality, architecture, technical decisions, maintainability, test quality/coverage, documentation, scope, current-main integration, versioning, CI, and delivery readiness.
- Added targeted iteration guidance while retaining the existing comprehensive final Story verification and CI gates.
- Added `tools/check-fast.ps1` plus `tools/fast-check-routes.ps1` for subsystem-aware local iteration checks. The router selects Core, transport, authority-lease service, version/media and existing feature-specific Godot harnesses from changed paths, suppresses production runtime checks for feature-doc-only edits, identifies extended/native checks separately, and emits manual/playtest scenarios where automation is insufficient.
- Added `tools/new-verification-report.ps1` to scaffold Story verification evidence and index entries without inventing results.
- Added `tools/test-workflow-tools.ps1` and wired it into both `check.ps1` and PR/main CI so verification scaffolding and fast-route decisions have a cheap regression gate. Route coverage includes vehicles, networking, settings/HUD, host migration, camera/manual verification, version/media, authority-lease service, fixed-step simulation, GdUnit, docs-only behavior and routed-script existence.
- Added explicit cost-efficient model selection guidance with no Light-tier recommendations: Sol — Medium, Astra Medium, Sol — High, and Astra Heavy selected by task complexity and expected rework; also added a canonical concise implementation-prompt shape and instructions to avoid bulk-loading unrelated feature/history context.
- Clarified that human-created local Story branches are the normal handoff and that implementation prompts should stay concise and rely on repository routing.
- Expanded safe post-push mechanical maintenance ownership for the independent PR review.
- Advanced the Story version from main `0.1.17` to `0.1.18` and synchronized the Windows export metadata.

- Raised the mandatory Astra runtime/experiential critique pass threshold from `6.0` to `8.0`; scores from `6.0–7.9` are now explicitly below the Trackstorm quality gate and require a meaningful improvement recommendation.

- Kept the independent ChatGPT engineering-review PASS threshold at `6.0/10`, intentionally separate from Astra's stricter `8.0/10` runtime/experiential quality gate.

## Assumptions and limitations

- `tools/check-fast.ps1` is an iteration helper only; it explicitly does not replace `./check.ps1`.
- Change classification is intentionally conservative: C#/project changes that are not clearly Core/Transport still trigger a Client Debug build.
- Verification-report scaffolding creates placeholders and never claims test results automatically.
- The implementation environment could inspect and write GitHub repository content but could not execute repository PowerShell scripts locally.

## Unresolved risks

- The dedicated Windows CI regression step passed on a reviewed pre-final head, reducing PowerShell syntax/helper-behavior risk. A fresh CI pass is still required on the final head after review-time corrections. The auto-routing path with a real `-GodotPath` remains dependent on future feature iterations exercising those routed harnesses.
- The fast-check path is intentionally an iteration layer; comprehensive `check.ps1` and CI remain final gates. Routed Godot checks can be required explicitly with `-RequireRuntime`, while extended/native checks require `-IncludeExtended`.

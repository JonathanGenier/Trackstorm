# TS-172 — Oil handling and pass-based lifecycle

## Approved correction — 2026-09-26

The user clarified: **“Any passes over oil. If same player twice, even owner.”** Jira TS-172 was updated with this decision and revised acceptance criteria before delivery. This supersedes the distinct-enemy lifecycle recorded in Round 1 below. The default is now **two separate successful passes by any vehicle**. Continuous overlap counts once; exiting and returning counts again. Owner passes consume the budget but award zero score. Each new enemy pass retains TS-156's 50 base points scaled by the owner's current K/D.

### Implementation and integration

- Patches retain their captured `PassLimit` and committed `PassesUsed`. Current per-life overlap latches prevent continuous contact from consuming another pass. Exit, death/reset or departure releases a latch without refunding the used count. Spent patches disappear at the authoritative commit boundary.
- Item protocol **13** preserves the count and current latches across publication, late admission, reconnect/resume and host migration. Restoring while still inside does not replay the entry or score. Validation permits owner latches and rejects duplicated/unaccounted latches and spent patches.
- F1 Oil now says **Vehicle passes before removal**. The existing `items.oil_enemy_contacts` storage key is retained for saved-tuning compatibility; the Core property is `OilPasses`. Defaults/ranges, category reset and existing applicable spawn tuning remain intact.
- The previously implemented grip/recovery, global-cap removal and bounded-message transport remain unchanged. No new dependencies or unrelated cleanup. Main remained `745796a`; Story/export versions remain **0.1.69 / 0.1.69.0**. The unrelated grass import change remains excluded.

## Implementation

- Removed the scripted yaw impulse. Supported Oil overlap reduces lateral tire force by default 50%, preserving steering, countersteering, longitudinal force and physical angular momentum. Leaving Oil restores grip linearly over default 1.75 seconds. Re-entry refreshes recovery; multiple patches do not multiply impairment. Movement snapshots retain recovery; retuning preserves its fraction with tick rounding.
- Removed the global deployment gate. Valid supported placement can consume held Oil while other patches exist. Each patch captures its owner, default two distinct-enemy budget and default 60-second absolute simulation deadline.
- Stable enemy identity counts once per patch across continuous/repeated overlap, new lives and reconnect. Owner overlap impairs handling but consumes no contact and scores nothing. Successful new enemies retain TS-156's 50 base points scaled by current owner K/D; lethal/reset candidates do not consume contacts. Core removes spent/expired patches and history. Retained owners remain eligible for credit after departure.
- Four host controls use **F1 → Configs → Oil**, existing staging, persistence, accordion and category reset: grip 0–0.8, recovery 0.1–10 seconds, enemy budget 1–7, cleanup 1–600 seconds. Existing Oil spawn tuning remains available.
- Extended complete item/resume/migration bounds and retained-owner award capacity. Item protocol 12, movement 9, configuration 23 and match 10 reject incompatible prior schemas.
- Client's shared reliable-message adapter compresses large boundaries when beneficial, sends remaining large payloads as paced 60,000-byte chunks and delivers only complete validated messages. Exact size/order, bounded allocation/backlog, malformed data, replay and timeout are covered. Gameplay consumers still validate authority/session/epoch/generation/revision. Unchanged Oil in ordered item updates references the preceding publication; changed Oil and standalone recovery checkpoints carry complete state, avoiding full patch retransmission with every projectile update.
- Core remains engine-independent; Client owns native framing/presentation. No Shared layer, native SDK change or new package/asset dependency.

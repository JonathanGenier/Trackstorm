### Leak cause and correction

The three leaked objects belong to native asynchronous resource loading, not to the configuration editor. A minimal GDScript SceneTree probe loads only `oval_foundation.tscn`, retains the returned PackedScene, waits twenty frames after completion, then quits. With dependency subthreads enabled it reproduces exactly three plain `RefCounted` objects at reference count zero. With dependency subthreads disabled the same probe exits without warnings. This reproduces the defect without C#, UI, settings, networking or a vehicle instance.

The native objects correspond to dependency `LoadToken` lifetime handling. Godot's [resource-loader implementation](https://github.com/godotengine/godot/blob/4.7-stable/core/io/resource_loader.cpp#L621-L634) releases the worker token with raw `unreference()`; that path does not delete a token when the decrement reaches zero. Distributing the oval's three external dependencies exposes this lifetime problem. Managed control disposal and delayed application quit do not repair native tokens already left at zero references.

`MatchResourceLoader` now requests `useSubThreads: false`. Each request still runs on a background worker; nested dependencies complete on that worker rather than being distributed to additional workers. Existing polling and `LoadThreadedGet` consumption, cached-resource retention, loading deadlines and synchronization gates remain intact. This is a scoped application-side mitigation of the engine lifetime defect, not an engine patch. No GC forcing, manual token disposal, warning filters, sleep-based shutdown workaround or test bypass was added. `check-developer-options.ps1` is unchanged.

The isolated probe and both diagnostic logs are saved in [ts-73-shutdown](ts-73-shutdown/). The full Developer Options strict wrapper now completes both processes, **494 write assertions and 8 fresh-process read assertions, with no ERROR or WARNING diagnostics**. Reset/Apply/default persistence, rejection/retry, revision ordering and UDP replication retain their original functional assertions. A rendered repeat passes **496 write assertions and 8 read assertions**, including screenshot captures, and also shuts down cleanly.

## Physics and handling

- Tire forces use a tangent basis projected onto the contact plane. Tire yaw velocities, torque and damping use the road normal rather than world Y.
- Four suspension rays follow chassis-down. Spring/damper force uses the support normal and each wheel's point velocity. Compression force acts through the actual scaled wheel lever arms. This retains tangential gravity instead of cancelling the bank's downhill component with vertical support forces.
- Tire capacity uses actual bounded spring/damper load, with normal gravity as the fallback for pure fixtures without wheel observations. Missing wheel forces already reduce capacity and are not counted twice.
- Forward engine demand falls continuously toward 44.44 m/s; the power curve is `1 - (v / cap)^4`, clamped to 0–1. Existing acceleration and cap settings govern it. No velocity snap or external-overspeed clamp was introduced; the existing 65 m/s safety bound remains.
- Handbrake application takes 0.25 s to reach full effect; full release recovery takes about 0.333 s. Rear grip remains 60% at full application. Mechanical braking/drive suppression end on release while grip recovers progressively. Countersteering and throttle use ordinary tire forces.
- Reduced chassis compliance limits load-induced lean without changing spring rates, vehicle scale or ride height. No new controller, scripted drift angle, forced yaw, racing-line assistance or downforce was added. Native tests establish stable support without downforce.

The existing incremental preload lists, threaded polling, cancellation draining and retained references are unchanged. The synchronous entry points preserve existing first-use timing, Godot's default cache reuse and consumer-held lifetimes. They introduce no static resource cache. Asset-domain checks keep application and match acquisition boundaries explicit. Audio still duplicates source streams before modifying loop flags; materials, scene instances, atlas crops and procedural geometry remain consumer-owned. The surface resolver's existing process-lifetime decoded-image cache is unchanged. Optional previews still return null when absent. Import reads remain uncached and bounded to 64 KiB, with strict UTF-8 decoding; the panel still checks session/epoch, parses into the draft and reports errors.

Re-audit: production Godot acquisition APIs remain only in `StartupController` and `MatchResourceLoader`; the remaining filesystem/native/embedded calls are the intentional owners below. This is a source audit, not a claim of exhaustive dynamic instrumentation or a compiler-enforced ban on future direct calls.

## Intentional exceptions

- `PlayerSettingsStore`, `DeveloperSettingsStore`, `ResumeLocatorStore`: existing specialized local persistence loaders retain file limits, schema/identity validation, freshness, atomic saves and fallback behavior. These are mutable user data, not imported Godot assets.
- `EosConfiguration.Load`: existing bounded, validated deployment override loader with credential-safe errors. It must remain independent of Godot asset caching.
- `LeaseEndpointConfiguration.Resolve`: owns its embedded assembly JSON and explicit environment override; validates the public HTTPS endpoint without requiring a Godot scene/resource.
- `GnsRuntime` and `EosProcessRuntime`: native DLL acquisition belongs to process-level SDK lifetime owners, with resolver and teardown semantics that a Godot resource loader cannot provide.
- `HttpLeaseTransport`: bounded live protocol responses, not asset acquisition; stays with the existing network transport.
- `code/Client/Verification`, test fixtures and the statistics verification-only `ChangeSceneToFile` in `SimulationBootstrap`: deliberately load isolated test assets/data and bypass presentation delays. They are not normal production entry paths.
- `assets/**/*.gd` acquisition calls are offline bake/preview generation or `EditorScenePostImport` hooks. Vendor `addons/gdUnit4` loading is editor/test infrastructure. Neither is production feature loading.
- Godot-authored `ext_resource` dependencies, project startup scene/icon and imported model dependencies remain engine-managed transitively. Procedural resources, resource duplication, native built-in fonts and texture-to-image decoding do not acquire external assets.

### Surface verification failure and correction

The initial surface run and isolated repeat passed behavior assertions but crashed during native finalizer shutdown with leaked-reference diagnostics. Temporarily built the unchanged HEAD/main Client sources, reproduced the same failure, then restored every modified source byte in a `finally` block and rebuilt successfully. A paced invocation also failed. This establishes a pre-existing fixture problem, not a passing baseline.

Corrected only `SurfaceIntegrationChecks`: dispose ray-query dictionaries from the large authored-map scan and keep final teardown on the Godot thread. Disposing dictionaries alone did not fix the crash. A scene-tree timer removed the fatal crash but still exposed exit leaks; a wrapper collection/drain produced a clean run, but independent Astra execution exposed intermittent leaks again before a formal score was issued. Verbose diagnosis identified all 68 retained objects as WAV/MP3 streams/playbacks, including an arena MP3. Clean repeats did not negate that failure.

The final fixture waits at least 250 ms of actual wall-clock time while advancing live scene-tree frames, then collects/finalizes transient wrappers and allows two additional frames before quitting. Fixed-fps simulation time alone cannot guarantee that the real audio mixer has processed deferred stream release. Five consecutive strict harness runs passed after this correction. No production cleanup or gameplay policy was changed. The initial failure, unchanged-main failure, intermediate clean run, independent intermittent failure and final repeated passes remain distinct evidence.

Initial sandboxed build failed during restore without a compiler diagnostic; rerunning with normal build access passed. The initial sandboxed resource harness completed 54 assertions but failed its strict log gate because Godot could not write user logs/read the certificate store. Normal-access rerun passed without those errors. These were execution-environment failures, not hidden passing runs.

## Limitations and risks

- No subjective listening, manual free-driving playtest, exported build, clean import/cache rebuild, separate-PC EOS or WAN validation. Native audio assertions establish playback/playlist state, not audible fidelity.
- Existing lazy loads can still block on first use; preload expansion and performance redesign were intentionally outside this behavior-preserving consolidation.
- Godot cache eviction timing and eventual garbage collection were not proven exhaustively. No new global retention was added; repeated lifecycle evidence is bounded to the exercised runs.
- Engine-managed transitive loading and vendor/editor test infrastructure remain outside the production call-site routing policy.
- No remaining known in-scope defect was exposed by completed checks. CI and independent post-push engineering review are separate delivery evidence.

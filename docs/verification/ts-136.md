# TS-136 verification evidence

Scope: TS-136 — Prevent automatic PR recreation for previously reviewed Story branches.

## Implementation

- Updated `.github/workflows/auto-create-pr.yml` so automatic PR creation checks all Pull Request history for the exact Story branch targeting `main`, not only open PRs.
- If any matching PR exists in any state, the workflow exits successfully without creating another PR.
- A branch with no prior PR history still creates exactly one PR when it is ahead of `main`.
- Updated `docs/workflow.md` to state that automatic PR creation is allowed only when the exact Story branch has no prior PR history targeting `main`.
- No Jira integration, automatic merge behavior, gameplay code, or runtime behavior was added.

## Verification

- The first pushed TS-136 commit ran the Auto Create Story PR workflow successfully and created PR #60 from `ts-136-jg` to `main`, verifying the no-history creation path still works.
- The workflow now uses `gh pr list --head <branch> --base main --state all`, so open, closed, and merged PR history for that exact branch/base pair is included in the suppression check.
- Subsequent TS-136 pushes are expected to detect PR #60 as existing history and exit without creating a duplicate; workflow-run evidence should be checked before final delivery.
- The implementation remains scoped to the exact head branch and `main` base.
- Story version and Windows export metadata must be synchronized to current `main` before final delivery.
- GitHub CI results are pending until the final Story version and documentation commits are present.

## Limitations / unverified

- The exact closed-PR and merged-PR post-merge scenarios cannot be destructively exercised on TS-136 without closing or merging its live delivery PR. Their behavior is covered by the same `--state all` history query used for the verified open-PR case.
- A later push to an intentionally closed historical Story branch after TS-136 merges is the clean production acceptance check for the closed-PR case.

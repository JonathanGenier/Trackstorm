# TS-288 verification

## Scope and implementation

Story: [TS-288 — Refine momentum advantage, pushing and off-center vehicle collision response](https://jonathangenier.atlassian.net/browse/TS-288). Implemented on the supplied `ts-288-pg` branch, initially clean. No branch switch or merge of main was performed, as explicitly requested. Canonical version is 0.2.36, with Windows export metadata 0.2.36.0, derived from the existing origin/main 0.2.35.

- Core pairs vehicle contacts before either participant's damage decision. Common incoming movement/effect velocities retain impact severity after native solving. One-sided reports damage both participants; matched movement ignores native support impulse.
- Received damage uses mass and linear momentum along the impact normal, with a bounded configurable bias (default 0.6). The stronger participant still loses speed and HP. Existing caps, cooldowns, attribution, reset/life filtering and spatial rear-shield interception remain authoritative.
- Low-speed forward/reverse engine demand gains a 1.6 multiplier at rest, fading quadratically to ordinary demand by 6 m/s. Existing supported tire capacity, mass scaling, handbrake interruption and speed limits remain. Chassis tilt follows tire force remaining after the rock constraint, before central Nitro thrust is added; canceled force cannot repeatedly pitch a blocked chassis away from the face. Throttle and tire-slip continuation remain ordinary.
- Shared geometry uses the centroid of distinct points on the strongest contact face. Center-side contact primarily translates. Front/rear side yaw uses the actual lever arm, impulse and effective mass, with bounded compliance before the shared impulse solve.
- PIT qualification accepts a wider rear-quarter band and slower moving targets. The 1.5 m/s closing-speed onset remains, protecting incidental rubbing. No scripted spin or new contact timer was added.
- Four Developer Configs keys expose low-speed demand, fade speed, off-center yaw response and momentum damage bias. Complete tuning wire: TC44, 230 values / 1861 bytes. Movement/world/checkpoint layouts are unchanged.
- Added deterministic combat tests, a native combat harness, slow/shallow PIT cases and impaired UDP momentum-role/stationary-target checks. Remote positions are compared at the same authoritative tick; prediction correction is measured separately.
- Expanded native fixtures drain freed wrappers before reusing native resource handles. This fixes observed Godot handle diagnostics during repeated fixture creation without changing gameplay or weakening assertions.

## Iteration findings and unresolved verification gap

- Initial low-speed demand reintroduced small blocked-rock fore/aft motion beyond TS-280 limits. Removing canceled tire force from chassis tilt fixed this; no rock acceptance threshold was relaxed. Existing throttle, tire-slip and immediate release tests remain intact.
- Lowering PIT onset during iteration made light taps too strong; onset was retained at 1.5 m/s. Wider rear geometry then passed both slow and shallow-quarter cases.
- A centered multi-point native contact initially selected an arbitrary corner and spun the target. Shared face-centroid geometry fixed it in authority and prediction.
- Symmetric damage initially bypassed an intercepted stationary rear shield. Explicit per-pair interception restored the existing spatial protection contract.
- Environment/PIT reruns exposed Godot GC-handle errors between freed fixtures despite passing physics assertions. Explicit wrapper draining resolved the diagnostics. Final environment, PIT and combat logs are clean.
- RockCluster landing contact mean exceeded the unchanged 8 ms budget in two earlier runs (8.62 and 8.42 ms). Final boosted run passed at 7.688 ms; the unboosted comparison passed at 7.115 ms. Boosted/unboosted positions were identical through frames 0–150, including the expensive observation interval. This supports timing variability in native observation rather than a different boosted landing trajectory; headroom remains limited. [Earlier strict failure](ts-288-evidence/completed-repeated-collisions.log) and [final pass](ts-288-evidence/final-v3-repeated-collisions.log) are both retained.
- **Supplementary Nitro harness remains failing.** Its unchanged first rocket scenario requires more than 8 m/s after roughly one second from rest, without throttle. Existing release values are 18,000 N thrust and 3,000 kg mass (6 m/s² before drag); both values and the expectation predate this change, verified against HEAD. This strongly indicates a stale fixture expectation, but an old-build native comparison was not run. Later Nitro harness stages were not reached, and failure shutdown also reported leaked resources. No production Nitro retuning or unrelated fixture-threshold change was made. Existing deterministic Nitro tests and the new two blocked-central-thrust tests pass; this does **not** turn the broader native Nitro harness into a pass.

- The broader native Nitro harness remains red for the numerical expectation described above; later stages are unverified.
- Native timing varies on this Windows host with the pre-existing editor running. Passing one mean budget is not a frame-time or low-end-performance guarantee.
- No independent PR engineering review was performed, and no PR was created or merged by this task.

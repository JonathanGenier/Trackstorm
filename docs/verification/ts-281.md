# TS-281 verification

## Scope and implementation

Jira TS-281, read in full on 2026-10-06, has no children or comments. The Story restores automatic aerial activation and changes its keyboard/controller defaults. No requirement changes were made.

- Core accepts aerial axes after 0.15 seconds continuously without tire support (ninth 60 Hz step). Tire support resets elapsed time and filtered intent; separate short gaps cannot accumulate.
- Removed the enable action from native bindings and the Controls editor. W/RT pitches nose-up, S/LT nose-down, A/D or left-stick horizontal yaws, and Shift/LB redirects horizontal intent to roll. Pitch remains available with the roll modifier held.
- Saved-default revision 3 migrates exact previous defaults and ignores retired activation overrides, preserving custom remaps and explicit unbinds. Legacy input bit 8192 remains decodable but is ignored by movement and never emitted by current bindings; input/wire layouts are unchanged.
- Existing body-axis rate/acceleration, release damping, ground handling, crash suppression and supported crash recovery remain under their existing owners. No attitude target, leveling or aerial recovery was added.
- Updated input, vehicle, settings, tuning and networking documentation. Story version is 0.2.31 / export version 0.2.31.0, based on current main 4f1c9e8db1bab010cc215389422c4d712b9d13b6 (0.2.30).

## Runtime observations

**VERIFIED:** Controlled rendered commands through `handling_playtest.tscn -- --handling-flat --automatic-air-playtest` used the production practice adapter and native keyboard/gamepad event capture. [Measurements](ts-281-evidence/playtest-summary.json) retain all direction trials and final pose, rate, support and HP observations.

- Held W produced zero air input and angular velocity through 8 steps / 0.13333334 seconds. The next accepted step recorded 0.15 seconds, pitch input 0.24253488 and positive pitch rate 0.26666668 rad/s. A sustained W reached 2.51954 rad/s nose-up. S produced the opposite direction.
- Each keyboard yaw/roll direction and each synthetic controller pitch/yaw/roll direction first produced aerial input on step 9. A/D selected yaw without Shift; Shift selected roll. RT/LT selected pitch; LB redirected stick yaw to roll. Analog magnitude 0.6 retained the expected conditioned magnitude approximately 0.5294 and proportionate angular rates.
- A real native 0.083333-second tire-support gap produced zero commanded aerial frames in both production adapters. Landing reset air continuation. The rendered short-gap run also remained at 1,000 HP and returned to tire support without aerial input.
- Releasing LB while holding the stick changed roll to yaw without disabling aerial control. Releasing directional input damped spin without changing the chosen attitude toward world-up; gravity and translation continued. The final rendered controller release had angular magnitude below 0.00001 rad/s.
- Both adapters completed four separate landing transitions in the repeated-jump scenario. Each of the three subsequent launches regained automatic yaw after a fresh airborne interval. Core tests additionally exercised twenty separate 8-tick gaps with support between them and snapshot/retune restoration at ticks 4, 8 and 9.
- Rendered captures were inspected for nose-up and barrel-roll pose. Segmented synthetic playtesting establishes direction, timing, continuity and visible motion; it does not establish physical-controller ergonomics.

## Iteration failures and resolutions

- Sandbox-only NuGet audit access initially produced NU1900; an authorized network-enabled forced restore resolved the cached audit failure. Final checks retained warnings-as-errors and did not disable audits.
- A sandbox-only aerial run completed its behavioral assertions but failed the diagnostic gate because Godot could not write user logs/read the Windows certificate store. Native-access reruns passed without those diagnostics.
- The first Core broad run found the old binding-default revision expectation (2); it was updated to revision 3 and all 1,168 tests passed.
- The old landing secondary-tumble fixture expected an uncommanded tumble to remain undamped. Automatic activation legitimately enables the existing neutral-axis damping, so this no longer guaranteed a damaging impact. The fixture now holds roll after its secondary impulse; unchanged damage/recovery assertions pass in all 64 cases. Production damage/recovery code was not changed.
- Two initial rendered spawn commands omitted the fixture-required `yaw` field and produced command-parsing errors. Those trials were excluded and rerun with complete commands; the saved summaries use the successful reruns.

- **UNVERIFIED:** physical keyboard/controller ergonomics, human free-play acceptance, remote-device/WAN/EOS aerial play, and exported builds. Local native adapters, synthetic native capture, Core prediction/restore and real local UDP regressions were exercised separately; they do not prove remote physical-controller play.

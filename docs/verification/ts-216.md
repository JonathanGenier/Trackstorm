## Implementation and scope

- Added Tombstone (wire identity 8) to the existing registry, two-slot grants and weighted pickup authority. Acquisition creates one stable entity ID and one independent 1000 HP pool.
- Added host-only forward lifecycle and damage contracts to `ItemAuthority`. Held and rear-shield state occupy the same physical slot; world-wall state releases it and captures a pose. Transitions never alter HP or ID. Retained respawn replaces only life/capability, preserving both held pools independently.
- Reused `VehicleHealth` damage clamping/destruction semantics on a separate pool. Ordered entity-scoped damage observations reject duplicate/stale hits; zero/negative requests cannot heal. Lethal damage removes the live entity, clears its attached slot and records one destruction event. Repeated damage or transitions cannot resurrect it or create another destruction outcome.
- Added complete health, stage, ownership, pose and replay-watermark data to the existing reliable item publication/codec and all production admission, reconnect and migration checkpoint paths. Item protocol is version 16; generated spawn-control schema requires gameplay configuration version 26. Validation rejects malformed state, inconsistent ownership, ID collisions and out-of-bound restore tokens.
- Added a three-peer native UDP/Godot core harness, 14 focused Core cases, weighted-pickup coverage and driver coverage for forged outcomes, stale publications and duplicate removal. Extended existing native reconnect/migration fixtures with exact damaged-wall records; all recovery fixtures now preserve the Tombstone set.
- Preserved Core/Client dependency direction. Added no assets, packages, generic item envelopes or alternate inventory. The only HUD change skips loading an absent Tombstone icon; dedicated HUD design remains outside this Story.
- Updated current item documentation and fast-check routing. Synchronized with `origin/main` before implementation and final verification; canonical Story version is `0.2.12` and export preset version is `0.2.12.0`.

## Assumptions, limits and explicitly unverified areas

- This Story supplies core lifecycle/damage contracts. Deployment input, physical rear protection, world-wall geometry, native collision/weapon target routing, models/VFX, dedicated HUD and competitive tuning belong to the later Stories and are deliberately unimplemented/unverified here. State transitions were exercised via host APIs.
- Tombstone's spawn weight defaults to zero until usable deployment exists. Explicit host grants and weighted pickups remain supported; this avoids changing ordinary loot behavior. The sixteen-live-entity bound follows existing bounded persistent-item practice and is not a final balance claim.
- Destruction uses removal from the complete live entity set, matching existing items. A newly acquired Tombstone receives a new ID and pool; retained respawn never does.
- Host damage adapters must allocate ordered entity-scoped observation sequences. Clients have no HP/damage/transition request. Physical hit interception will need to feed this contract in the later deployment Stories.
- Native multiplayer evidence is local to one Windows PC. Reconnect/migration authentication uses trusted test identity seams. Remote authenticated EOS, independent PCs/NAT, cross-platform physics and long-session/network soak were not exercised. No such evidence is claimed.
- No new third-party dependencies or assets were introduced. No unresolved in-scope runtime failure remained after verification; the future physical/native-hit integration remains a known boundary.

## Scope and approved controls

Implemented the Story in the existing PlayerInputAdapter, binding/preferences owner and VehicleChaseCamera. No parallel camera, authoritative gameplay rule, network field, version file or index change. The user approved D-pad Up during gameplay only; Jira description was synchronized with that decision. Up/Down/Left/Right retain menu navigation, Left retains discard, and Tab/Select/View retain leaderboard access. New photo actions participate in existing rebinding and persistence.

C/D-pad Up toggles. WASD/left stick translates, mouse/right stick looks, E/Q and RT/LT ascend/descend. Shift/RB selects 40 m/s travel; Ctrl/LB selects 0.6 m/s precision; default is 6 m/s. Translation eases at 18/s. Forward/back movement supplies close/wide framing without changing saved FOV. Free travel is intentionally non-colliding; near clip is 2.5 cm until exit. Camera axis gains/inversion are reused.

Photo mode neutralizes vehicle/aerial/item capture, resets targeting, removes Salvo guides and avoids desired-aim submission before network advance. The simulation continues normally. Exit restores the configured chase view, original near clip and reset presentation memory. Held gameplay/look controls require release; a neutral capture boundary prevents queued weapon presses crossing rapid toggles. Focus, menus, diagnostics, lifecycle/recovery and teardown exit photo mode.
